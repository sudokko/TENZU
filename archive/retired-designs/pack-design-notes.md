## 4. 設計判断の根拠

### なぜ「設問タイプ × 難易度」が主軸か

- **Job A**（「回転が苦手」）→ タイプで選べる。競合に一切ない切り口
- **Job E**（「一ヶ所で揃えたい」）→ 難易度で選べる
- **学習上の意味**を持つのはこの2軸だけ。モチーフやレイアウトは学習効果に影響しない

### なぜグリッドを別格扱いするか

- 線分数や斜め角度 → 親が見ても認知できない（内部パラメータ）
- グリッド数 → **見た瞬間にわかる**唯一の内部パラメータ
- 親は「4×4はできるけど5×5はダメ」のようにグリッドで子どもの実力を把握している
- 競合ブログ（hahatokotime等）もグリッドサイズで学習段階を説明している

### なぜモチーフは「バリエーション」か

- モチーフは「楽しさ・取り組みやすさ」の軸であり、学習効果は同じ
- 同じ設問タイプ×難易度の中で、モチーフ違いのバリエーションを出す
- 「飽きたら別モチーフで同じ練習」ができる

### なぜ導線は複数入口か

- 親の状態によって探し方が異なる（「回転が苦手」vs「5×5がちょうどいい」vs「動物の絵で楽しく」）
- **商品の切り方は1つ、見つけ方は複数** = ユニクロのTシャツ型

## 6. 課金・パック設計の方針（2026-04-05 議論）

### 6.1 Stripe技術検証（確定）

| 要件 | 実現方法 | 複雑度 |
|---|---|---|
| 複数パック一括決済 | Checkout Session + line_items（最大20アイテム） | 低 |
| 数量割引（自動適用） | サーバー側で数量判定 → Coupon自動付与 | 低〜中 |
| 最低購入額 | サーバー側バリデーション（if文） | 低 |
| ウォレット/チャージ制 | **不採用**（資金決済法の供託義務リスク＋実装過剰） | — |

- Payment Linksは動的カートに対応不可 → **Checkout Session API一択**
- Stripeの最低処理額は日本円で¥50
- Stripe手数料: 3.6% + ¥40/件

### 6.2 パック粒度と価格：5案の検討結果

海外事例調査（Gemini Deep Research × 2回）＋Claude分析で5案を比較検討。

| 案 | 概要 | 判定 | 理由 |
|---|---|---|---|
| A: 小パック×多SKU | 10問¥150、最低¥300 | ❌ | 手数料負け。海外でもアンチパターン |
| B: 中パック単層 | 30問¥400 | △ | 束は正解だが入口がない |
| C: 2層型（エントリー＋本命） | 10問¥200 + 30問¥450 | **✅構造採用** | 両調査とも「薄い入口＋束の本命」を支持 |
| D: バンドルはUIの仕事 | SKUは単品のみ。縦横バンドルはUI提案＋自動割引 | **✅採用** | 別SKU管理不要。TPTの商品ページ内アップセルと同じ思想 |
| E: レベル横断まとめパック | 同レベル×全9タスクの詰め合わせ | **❌** | タスク間で難易度が異なるため横断レベルが成立しない |

**採用方針: 案C（2層構造）＋ 案D（バンドルはUI）の統合**

```
【確定した構造】
・SKUは単品（タスク×難易度×10問）のみ管理
・UIで「おすすめ組み合わせ」を提案（縦：同タスク複数レベル / テーマ別）
・複数パック購入時にサーバー側で自動割引（常設20〜30%）
・最低購入額は設けない（割引インセンティブで平均注文額を上げる）
・期間限定セール（年4〜6回）と常設割引は分けて運用
```

### 6.3 価格帯（未確定）

- 海外調査は$3.50〜$4.99（¥500〜700）を推奨したが、ドルベースのため日本市場にそのまま適用は危険
- 元のClaude案（¥150〜¥450）の相場観の方がオーナーの感覚に合う
- **手数料との兼ね合いで最低ラインは要検討**（¥100だと手取り¥56で利益率56%）
- → 価格は難易度設計が固まった後に最終決定

### 6.4 割引構造（方向確定、詳細未定）

| 種別 | 内容 | 根拠 |
|---|---|---|
| 常設割 | 複数パック購入で20〜30%OFF | Math Mammoth型（33-35%）、TPT型（32%） |
| 期間限定 | 年4〜6回、15〜25%OFF | 新学期・長期休み等のタイミング |
| 常時大幅値引き（70%+） | **不採用** | Etsy文化を自社サイトに持ち込むとブランド毀損 |

## 7. 難易度設計の根本問題（2026-04-05 発見）

### 7.1 タスク横断レベルは成立しない

「回転Lv3」と「拡大Lv3」は**同じ難しさではない**。子どもによってタスクごとの得手不得手がある。
→ **タスク横断の統一レベル体系は作れない**（作っても意味がない）
→ 「うちの子はLv3だからLv3を全部」という買い方は成立しない
→ 「うちの子は回転が苦手 → 回転を段階的に」が自然な買い方

### 7.2 タスクによって難易度の変数が異なる（仮説）

| タスク | 難しさの本質（仮説） | グリッドサイズの重要度 | 必要なレベル数（仮） |
|---|---|---|---|
| 模写 | 線の多さ・グリッドの大きさ | **高** | 多い（模写は7 Vol.確定） |
| 立体模写 | 奥行きの理解 | **高** | 多い？ |
| 欠け補完 | 元の図を推測する力 | 中？ | 中？ |
| 回転 | 「回転する」概念の理解（90°/180°） | 低？ | 少ない？ |
| 線対称 | 「反転する」概念 | 低？ | 少ない？ |
| かさね | 2つの図を重ねる概念 | 低？ | 少ない？ |
| 拡大・縮小 | 比率の概念 | 低？ | 少ない？ |
| 平行移動 | 位置をずらす概念 | 低？ | 少ない？ |

**→ 「8タスク × 一律N段階」ではなく、タスクごとに段階数が異なる設計が自然**

### 7.3 未解決の問い（次回セッションの出発点）

1. **各タスクの「何が変わると難しくなるか」を明確にする**
   - 模写はグリッド＋線分数＋斜め → 分かりやすい
   - 回転・対称・かさね等は？ 概念の難しさは何段階に分けられる？
   - 実際に子どもにやらせた感覚があればそれがベスト
2. **模写だけ特別扱い？** → 模写が10段階、他が3-5段階なら、模写がTENZUの主力商品？
3. **「グリッドサイズが重要でないタスク」はそもそも細かいレベルが要るのか？**

## 8. 海外調査で得た補足知見（2026-04-05）

### 参考にすべきパターン
- **TPT「バンドル階段」**: 商品ページ内で「Save even more with bundles」を常時提示 → TENZUも同タスクの上位パック・関連タスクを常時表示
- **Math Mammoth型**: 常設バンドル割33-35%を明示。価格の信頼性を保つ
- **無料サンプルの段階化**: ゲートなし（1-3問）＋メアド登録（大量体験）の2段構え

### 避けるべきパターン
- Etsy型「常時70%OFF」→ ブランド毀損
- 過度な細分化（1-2ページを$0.50で売る）→ 手数料負け＋選択疲れ
- 返品不可商品の説明不足 → 購入後不満で二度と買わない

### デジタル商品特有の注意点
- DLできない/印刷がずれる等のFAQページは必須
- 購入完了メール＋マイページの両方からDL導線
- 推奨印刷設定（A4、余白、グレースケール等）の明示

## 9. 模写タスクの難易度変数（2026-04-07 議論）

### 9.1 前提：印刷PDF前提で仕分け

難易度変数と**全問共通の品質基準**は分けて管理する。品質基準は別途「TENZU印刷仕様書」として固定する。

### 9.2 品質基準として固定（難易度変数から除外）

- ドット間隔 / 盤面アスペクト比 / 補助線の濃さ / 解答欄のドット表示 / お手本の位置 / 手本と解答欄のサイズ比 / お手本のグリッド明示度 / 問題と解答欄の距離 / 1ページの問題数 / 線の細さ・印刷濃さ / 印刷スケール

### 9.3 模写の難易度変数（14軸）

**A. 盤面**
1. グリッドサイズ

**B. 線の構成**
6. 線の総本数
7. 線分の長さ分布
8a. **斜め線の有無**（縦横のみ / 斜めあり）
8b. **斜めの角度種類**（45°のみ / 1:2・1:3等の非45°あり）← 2026-04-07 分解
8c. 斜め線の本数比率（少数アクセント / 主構成）
9. 線の交差数
10. 線の重なり
11. 頂点の数
12. 線の連続性（一筆書き可否）
13. 閉図形の有無

**C. 認知**
14. 記憶フックの有無（意味性の難易度成分）
15. 対称性（線対称）
16. 規則性
17. 構成要素数
18. 始点の見つけやすさ

### 9.4 分解の根拠：斜め（8a/8b）

45°と非45°（1:2, 1:3等）は**認知処理が別物**。
- 45°は縦横の延長線上で処理できる
- 非45°は「2マス右・1マス下」の2軸同時認識が必要
- 実際に1:2斜めが入ると正答率がガクッと落ちるのが経験則
→ 独立した難易度変数として切り出す。
