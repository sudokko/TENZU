# 書籍216問の購入者特典の公開手順

## サマリ

- 表紙デザインはオーナー担当。以下の既定の生成・検査は本文・購入者特典・A+のみを扱い、表紙を変更しない。
- 書籍特典の入口は `/book/216`、コード確認は `/api/book/216/unlock`、PDFは認証後の専用APIから配布する。
- 配布PDFは `web/private/book-216/`。公開ディレクトリへ置かない。Next.jsのトレース設定でSSRに同梱する。
- コード原文はGit除外の `web/.local/book-216.json`、本番にはSHA-256だけを設定する。
- 本番で必要な変数は既存の `AUTH_SECRET` と `BOOK_216_CODE_SHA256`。値をコミットしない。
- 特典は固定期限なし。30日cookieの失効後も、本のコードで再取得できる。
- 書籍コードは既存Stripe商品の所有権を発行しない。共通コードは厳密な購入証明ではない。
- 本番公開前にコード・配布PDF・入稿本文の一致、全11ファイルの同梱、未認証アクセス拒否を確認する。

## 詳細

### 制作と検査

`web/` から以下を順番に実行する。既存コードを作り直さないようsetupは保存済み設定を再利用し、不一致の環境変数があれば停止する。

```powershell
npx tsx scripts/setup-book-216.ts
npx tsx scripts/check-book-216.ts
npx tsx scripts/export-kdp-book.ts --out ../docs/drafts/kdp/first-patterns-216/publication-revision
npx tsx scripts/export-book-216-benefits.ts --out ../docs/drafts/kdp/first-patterns-216/publication-revision
python scripts/preflight-kdp-book.py --out ../docs/drafts/kdp/first-patterns-216/publication-revision --render
python scripts/preflight-book-216-benefits.py
npm run build
```

A+だけを更新する場合は `export-book-216-benefits.ts --assets-only` を使い、配布PDFを保持する。過去の比較表紙は明示的な `--with-cover-comparisons` がなければ生成されない。

検査はpypdf・pdfplumber・PillowとPopplerを使う。PDFスキルを使う作成・改訂セッションでは、そのスキルの開始マーカーを最初の制作前に実行する。

開発サーバーを起動した状態で `npx tsx scripts/check-book-216-http.ts` を実行すると、未認証・不正コード・改ざん・連続入力、全11配布PDFのハッシュと主要ページの応答を確認する。`BOOK_TEST_URL` で確認先を指定できるが、不正コード連続入力の検査を含むため、通常はローカルまたはstagingを使う。

### 受取ページの詳細設定

認証後に「自分に合う紙面にする」を開くと、書籍の18巻を本の問題番号（12問ごと）で選べる。用紙6種類・問題数・並び・点の大きさ・名前と日付の記入欄・背景の点は、既存の購入後画面の [SkuPrintPreview](../web/app/products/SkuPrintPreview.tsx) をそのまま共用する。設定版は既存Web商品の形式で保存し、本の通し番号付きA4固定PDF11ファイルも残す。Lv.4への9種類のリンクは認証前後とも折りたたまず常時表示する。

問題データは `/api/book/216/volumes/[sku]` で、書籍cookieを検証してから返す。書籍収録SKUの許可リストにない巻は404、未認証と改ざんcookieは401。元データと描画写像は既存のpublished JSONと `toRenderProblems` を使い、問題を複製しない。応答は `private, no-store` と `noindex`。設定画面とデータは、開いたときに読み込む。

HTTP検査は18巻216問の一致と、書籍にないレベルの拒否も確認する。画面では平面・かさね系・立体を切り替え、用紙・並び・点・名前欄・背景点がプレビューと保存PDFへ反映されることを確認する。

### 本番環境への設定

1. Amplifyのmainブランチに `BOOK_216_CODE_SHA256` を設定する。値はローカルで生成済みのハッシュを使う。コード原文や `AUTH_SECRET` をログ・メッセージ・Gitへ貼り付けない。
2. `amplify.yml` の環境変数許可リストがこのキーを `.env.production` へ渡すことを確認する。
3. `web/private/book-216/` の11ファイルを、今回のコードと同じリリースに含める。Next.jsのファイルトレースに含まれることをビルド出力で確認する。
4. 本文4ページのコードで取得できること、サーバーの配布ファイルと生成manifestのハッシュが一致することを確認する。
5. 未認証のPDF直アクセスは401、未知のファイルIDは404、配布応答は `private, no-store`、`noindex` であることを確認する。

コードの設定値が欠けている場合は、受取APIを503で停止する。固定の開発用コードへフォールバックしない。PDF不足も成功扱いにしない。

### コードの変更と運用

`BOOK_216_CODE_SHA256` はカンマ区切りで複数のハッシュを保持できる。コードを変更する場合も、すでに印刷された本のコードを無効にしない。入口URLは維持する。配布場所の変更・障害・訂正は受取ページに案内を残す。

連続した不正コード入力はインスタンス内で補助的に制限する。分散したアクセス全体に対する厳密な制限ではない。共通コードの転送や試し読みへの掲載は防ぎ切れないため、注文情報を検証した購入認証とは表現しない。

PDF更新時は同じ問題番号と元問題IDを維持し、版・更新日・訂正内容・manifestを更新する。今回の制作改訂では、本の201ばんに当たる `fold-lv3-vol1-m09` の出題図を訂正している。完成図の意図を保った修正で、Web商品の改訂履歴にも記載する。

### 計測と確認

- 書籍QRのUTMと3種のイベント定義は [analytics.md §9](analytics.md) を参照する。
- PCとスマホで、入力エラー、再取得、PDF保存、A4白黒印刷、問い合わせ、次レベルの実商品へのリンクを確認する。

### 公開前にオーナーが確認するもの

本文の使い方、購入者特典の紙面、実際の受取ページを確認する。表紙はオーナーが制作し、入稿時に登録する題名・副題と照合する。表紙の制作・確認を、本文・サイトのローカル検証の前提にしない。校正刷りでは線・点・裏写り・のど・QR・バーコード・ページ順を確認する。最終出版の操作、価格とAI申告の確定はオーナーが行う。
