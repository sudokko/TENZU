# TENZU リリース戦略

## サマリ

- フィードバック駆動型・4フェーズ構成（Phase 0/1/2/3・合計2.5-3.5ヶ月）
- 主目的=集客／副目的=ブラッシュアップ／**非目的=売上**（先行期はゼロでOK）
- 経路分離：インフルDM経路と先行モニター経路は完全独立
- アプリ先行：Phase 0 ではアプリ＋最小LP＋初期記事10本のみ公開
- 4通DM構造：1通目（アプリ紹介）／2通目（紹介発生時お礼）／3通目（Phase 1 開始時モニター案内）／4通目（Phase 3 本リリース＋読者用クーポン）
- 先行モニター：10名前後・全SKU無償フルアクセス・LP公募中心
- クーポンは Phase 3 のみ・Stripe Promotion Code で1 SKU 100% OFF
- 詳細は [phases.md](phases.md)（各フェーズ詳細）／[monitor.md](monitor.md)（モニター制度）

## 詳細

### §1. 目的・成功定義

#### 1.1 主目的・副目的・非目的

| 区分 | 内容 |
|---|---|
| **主目的** | 集客＝インフル/ブロガー経由で TENZU の認知を広げる。アプリを「紹介する口実・フック」として機能させ、コールドスタート期の指名検索・SEO評価の土台を作る |
| **副目的1** | サイトUX・設問構成のブラッシュアップ。先行モニターからの声を反映 |
| **副目的2** | ニーズ把握。どの年齢・タスク・難易度のSKUが刺さるかを定性データで掴む |
| **非目的** | **先行期間で売上を作ること**。極論ゼロでよい。販売検証は本リリース以降 |
| **歓迎するもの** | 濃いコミュニケーション・直接フィードバック・継続的な関係構築 |
| **避けるもの** | サンプルPDF配布等の薄い接点／投稿依頼の押し付け／販売を前面に出す訴求 |

#### 1.2 成功の定量定義

| 観点 | 最低ライン | 推奨ライン |
|---|---|---|
| 先行モニター獲得 | 5名 | 10名以上 |
| フィードバック回収率 | 60% | 80%以上 |
| 改善反映件数 | 5件以上 | 10件以上 |
| インフル/ブロガー言及 | 2件 | 5件以上 |
| アプリ累計利用 | 200回 | 500回以上 |
| メール/LINE登録 | 50件 | 150件以上 |
| Stripe・DLフロー検証 | エラー0件 | エラー0件＋本リリース時の決済フロー全パターン確認済 |

#### 1.3 中断条件（NoGo判定）

以下のいずれかが発生した場合、本リリース前に再設計を検討：

- 先行モニター 3名未満で募集が止まる
- アプリの致命的バグ多発・修正不能
- フィードバックが「コンセプト自体への否定」に集中

#### 1.4 段階1（先行）と段階2（本リリース）の本質的な違い

| 観点 | Phase 0-2（先行） | Phase 3（本リリース） |
|---|---|---|
| 役割 | **学習と関係構築** | **販売と認知拡大** |
| 主アクター | 先行モニター10名前後 | 一般ユーザー全層 |
| 商品状態 | 修正前提・未完成OK | 自信を持って完成版 |
| 価格 | 無償（先行モニターのみ） | ¥200一律 |
| 集客 | 質重視・少数深く | 量重視・広く |
| KPI | フィードバック質・改善反映数 | PV・CVR・売上 |
| 失敗の代償 | 軽い（修正で挽回） | 重い（ブランド毀損） |

### §2. 4フェーズ構成（Phase定義の一次ソース）

#### 2.1 全体タイムライン

```
T-3.5M ────────────────────────────────────── T=0（本リリース）
│         │                  │                │
Phase 0   Phase 1            Phase 2          Phase 3
1-2週     4-6週               4-6週            ≥1週
公開      先行モニター        修正期間         本リリース
```

合計 **9〜14週間（2.5〜3.5ヶ月）**

#### 2.2 各フェーズの位置付け

| Phase | 期間 | 主目的 | 公開記事 | 終了条件 |
|---|---|---|---|---|
| **Phase 0** | 1-2週目 | アプリ＋最小LP＋初期記事10本公開／DM 1通目開始 | 10本（アプリ紹介1＋Pillar A 1＋症状ベース5＋ノウハウ3） | インフル実反応 5名以上 |
| **Phase 1** | 3-8週目 | サイト本体オープン＋先行モニター募集＋フィードバック収集 | +7本（商品ファミリー4＋#17＋FAQ 2／累計17本） | モニター10名・フィードバック8割回収 |
| **Phase 2** | 9-12週目 | フィードバック反映でサイト・設問・UXを修正 | 追加なし | 修正版再評価合格、または4-6週経過 |
| **Phase 3** | 13週目〜 | 全SKU公開・¥200一律で正式販売開始＋DM 4通目（読者用クーポン配布） | +36-37本（累計53-54本） | 継続運用フェーズへ |

各フェーズの公開物・施策・DM構造・KPIは [phases.md](phases.md) 参照。

#### 2.3 ユーザー視点での3段階呼称（参考）

| 3段階呼称 | 4フェーズ対応 |
|---|---|
| ① アプリリリース | Phase 0 |
| ② 先行リリース | Phase 1 + Phase 2 |
| ③ 本リリース | Phase 3 |

設計書内の正式表記は **4フェーズ表記（Phase 0/1/2/3）** で統一。

### §3. 経路分離の原則

インフルDM経路と先行モニター経路は **完全独立**：

| 経路 | 目的 | 終着点 |
|---|---|---|
| インフルDM | 認知拡大・読者経由流入 | Phase 3 で読者用クーポン配布（DM 4通目） |
| 先行モニター | サイトUX・設問のブラッシュアップ | Phase 3 で TENZU 開店記念ギフト |

DM 1通目で両者をバンドルしない。詳細は [phases.md §3-§6](phases.md) を参照。

### §4. 先行モニター制度（要約）

| 項目 | 値 |
|---|---|
| 呼称 | **TENZU 先行モニター**（暫定） |
| 規模 | 10名前後（最低5名・上限20名） |
| 募集 | Phase 1 開始時から開始。第1優先：LP公募／第2優先：DM 3通目／第3優先：X/note/LINE公募 |
| 提供 | 全SKU 無償フルアクセス＋アプリ無制限利用＋直接連絡チャネル |
| 期待 | フィードバック必須（Google Form/LINEアンケート＋直接やりとり） |
| 投稿 | 任意（ステマ規制対応で提供品である旨の明示前提） |
| 謝礼 | 本リリース時に「TENZU 開店記念ギフト」（新規SKU 5本程度の無償継続提供） |

詳細は [monitor.md](monitor.md) を参照。
