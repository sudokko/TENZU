### §2. 共通方針

#### 2.1 アプリ本体メアド方針

- アプリ本体は **メアド不要** 堅持（投入時）
- LP上の任意メール/LINE登録のみ許可（本リリース通知用）

- 投稿依頼はしない
- 自発的紹介の場合は提供品である旨の明示を依頼前提
- 読者用クーポン配布時（Phase 3）も同様に明示依頼

#### 2.4 上から下波及法則（2026-05-20 案F・Gemini案E）

集客戦略の核：**中受 P3-a に全振り**することで、X 実況・口コミバズが低学年予防層 P2-a・学校算数フォロー層 P2-b へ**権威付け波及**する。

```
P3-a（中受緊急・X実況力強）
  │  口コミ・X実況・記事シェア
  ↓
P2-a（中受2-3年備え）／P2-b（学校算数フォロー）
  │  権威付け波及（「中受層も使っている」）
  ↓
P1-a／P1-b／P4／P5（受動拾い）
```

### §4. Phase 2: 修正期間（7-10週目）

#### 4.1 期間

T-1M 〜 T=0（7〜10週目・4週間）

#### 4.2 反映方針

フィードバックを **3カテゴリ**で分類：

1. **致命的（Phase 3 GO の必須条件）**: バグ・誤情報・致命的UX不備
2. **重要（本リリース前に反映したい）**: 使いにくさ・設問の難易度ズレ
3. **将来課題（Phase 3 後でOK）**: 機能追加要望・新タスク要望

致命的＋重要のすべてを Phase 2 で対応。将来課題は OPS バックログへ送る。

#### 4.3 修正版の再評価

- 修正完了後、先行モニター10名に「再評価依頼」（任意）
- 主要修正点を簡潔にまとめた「変更ノート」を共有
- 再評価で重大な問題が出なければ Phase 3 GO

#### 4.4 KPI

| 指標 | 目標 |
|---|---|
| 致命的フィードバック対応率 | 100% |
| 重要フィードバック対応率 | 80%以上 |
| 修正版再評価合格 | 先行モニター 6名以上の合意 |

### §8. ポスト・ローンチ：アプリ投入（運営判断・別個に実施）

#### 8.1 位置付け

- Phase 3（本リリース）には**含めない**。本リリース後、運営判断で**適切なタイミング**を見極めて別個に実施
- 2026-05-20 案F確定：Phase 0 廃止に伴い、アプリは「Phase 0 の主役」から「ポスト・ローンチの追加レイヤー」へ降格
- アプリは「TENZU の体験を深める無料ツール」として後付け投入する位置付け

#### 8.2 投入判断条件（運営判断・目安）

| 条件 | 目安 |
|---|---|
| 本リリース後の運営安定 | Phase 3 開始から最低3ヶ月経過し、サイト・販売フローが安定稼働 |
| 月間 PV | 5,000 以上（記事流入が安定） |
| 自己診断ツール完了数 | 月 500 以上（ファネル上流が機能している） |
| 開発リソース余裕 | 既存記事・SKU 運用に追加の運用負担をかけずアプリ実装に着手できる |
| アプリの価値検証 | 既存ユーザー・先行モニターから「アプリ欲しい」の声が一定数集まる |

すべて満たさなくてもよいが、複数満たしたタイミングで投入を決断する。

#### 8.3 投入時の追加作業（スコープ感）

- C-5a アプリ実装完成（Next.js + サブドメイン `app.tenzu.〇〇`）
- アプリ専用 LP 1枚（Phase 0 の旧 LP 設計をベースに再評価）
- DM・記事 CTA・LP に「無料の作成アプリ」セクション追加
- D5 アプリプロト → 本実装の流れ

#### 8.4 投入しない選択肢も維持

- 市場反応次第では**アプリ投入を実施しない**選択肢も維持
- 「ポスト・ローンチで投入することがある」程度の柔軟運用にとどめ、Phase 1-3 のスコープからは完全に切り離す
