# リリース前テスト計画

## サマリ

- リリース前テストの観点一覧と AI 委任範囲の SSOT。実施用チェックリストの複製は Notion「TENZUリリース前テスト計画」（チェックはNotion側でつける・観点の変更はこのファイルが正）
- 優先順は4段: **P0 お金と受け渡し／P1 無料の入口とスマホ／P2 紙とことば／P3 計測と見え方**（§2〜§5）
- 個人店は初期の客が少ないぶん「払ったのに届かない」事故1件が致命傷。網羅よりも **P0 の完走を最優先**（§1）
- 進め方は2段階: **テストモードで P0〜P3 を一巡**（本番 env 前の今できる）→ **本番化後に P0 だけ再走**（公開直前リハーサル・§7）
- 人間にしかできないのは4つ: **実カード決済・メール受信・紙への印刷・スマホ実機**。人間の持ち時間は合計 約5〜6時間＝週3ブロック × 2週分（§7）
- AI 委任の線引き: **読む・照合する仕事＝Haiku 級**／**スクリプトを書いて動かす仕事＝Claude Code**／**現物に触る仕事＝人間**。依頼文テンプレは §6
- 見つけた不具合はこのファイルに書かず [phase-1-todo.md](phase-1-todo.md) へ ★/P1/P2 で追記して1件ずつ潰す
- 受容済みの割り切り（webhook 重複メール・問題データのソフトゲート等）はバグ扱いしない（§8）

## 詳細

### §1. 考え方 — 何を守るためのテストか

個人店の信用は「最初の数十人」の体験で決まる。守る順番は次のとおり。

1. **お金と受け渡し**: 「¥200 払ったのに PDF が出ない」「¥980 払ったのに工房が開かない」は返金では済まない（SNS で語られる事故）。→ P0
2. **無料の入口**: ほとんどの訪問者は買う前に無料の工房・サンプルに触る。ここが動かないと購入まで進まない。→ P1
3. **商品そのもの**: 印刷した紙がにじむ・薄い・誤字がある、は静かに信頼を削る。→ P2
4. **計測と見え方**: 壊れていても客は困らないが、運営判断が狂う。公開後でも直せる。→ P3

テストの合格ラインは「P0 が全部緑」。P2・P3 の残りは公開後の週次ブロックで拾ってよい。

### §2. P0 お金と受け渡し（最優先・人間 約2時間＋本番再走1時間）

Stripe テストモード（カード番号 `4242 4242 4242 4242`・お金は動かない）で一巡し、本番化後に §7 の再走をやる。

#### 紙（プリント ¥200）

- [ ] カートに2巻入れて購入 → サンクスページに2巻とも「購入済み」で表示され、PDF がダウンロードできて開ける
- [ ] 購入確認メールが届き、メール内のリンクから**別のブラウザでも**再ダウンロードできる
- [ ] 決済画面で「戻る」→ カートの中身が消えていない
- [ ] コンビニ払い等の後払い: 支払い確定前にサンクスページへ戻ると「お支払いを確認しています」が出て、（テスト画面で支払いを確定させると）自動でダウンロード画面に切り替わる
- [ ] でたらめな `session_id` でサンクスページを開く → エラー文とカートへの戻り導線が出る（白画面・500 にならない）

#### 工房（メーカー ¥980）

- [ ] 未購入で PDF 書き出し → 購入ゲートが出る（素通りしない）
- [ ] ¥980 購入 → maker-thanks に到着 → その場で書き出しが解禁されている
- [ ] ブラウザを全部閉じて再訪 → 所有が残っている
- [ ] 2個目のメーカーを買い増し → 1個目の所有が消えず両方使える（cookie マージ）
- [ ] 模写メーカー: 4×4 は無料で書き出せる／5×5 以上は購入ゲートが出る

#### 復元（マジックリンク）

- [ ] シークレットウィンドウ（＝別端末のつもり）で /login → メール → リンク → /account に所有が全部戻る
- [ ] 期限切れ・使用済みリンク → エラー表示に落ちる（無言で失敗しない）
- [ ] 購入時と大文字小文字が違うメールアドレスで復元をかけたとき、購入履歴を拾えるか

#### メールと webhook（本番化後）

- [ ] SES サンドボックス脱出後、Gmail 等のフリーメール宛てで受信でき、**迷惑メールに落ちない**
- [ ] Stripe ダッシュボード → Webhook の配信履歴が「成功」になっている
- [ ] 実カードで ¥200 を1回自分で決済 → PDF・メールまで全部届いたら Stripe から返金

### §3. P1 無料の入口とスマホ（人間 約1.5時間）

- [ ] 公開9メーカー全部: 白紙から描く → 保存 → 無料範囲で PDF 書き出し → 開ける（1メーカー5分の流し）
- [ ] 消す・やり直し・保存済みの編集など、基本操作で詰まらない
- [ ] 非公開メーカー（拡大・縮小）が /makers に出ていない
- [ ] `MAKER_DEBUG_OWN_ALL` が本番ビルドで効かない（未設定で全所有になっていない）
- [ ] **スマホ実機2台**（iPhone Safari／Android Chrome）: タッチで線が引ける・上部メニュー操作・PDF の保存先・購入フロー完走
- [ ] TOP → 品ぞろえ → 商品詳細 → カートの導線が切れ目なくつながる（TOP のアニメ実演含む）
- [ ] ヘッダー・フッター・記事内リンクに切れがない（AI のクロールスクリプト併用・§6）

### §4. P2 紙とことば（人間 約1時間＋AI）

- [ ] **実印刷**: 9タスク代表1巻ずつ＋解答ページを家庭プリンタで印刷。A4 余白・点の濃さ・線の太さ・文字のかすれを見る
- [ ] **コンビニのマルチコピー機で1枚印刷**（家庭にプリンタがない客の代表環境）
- [ ] 公開42巻の中身スモーク: 巻タイトル・問題数・盤面が商品ページの表記と一致（スクリプト向き・§6）
- [ ] ことば一式を AI で総ざらい: NG 語（voice-tone §1）・誤字脱字・価格/巻数の食い違い・「点図形（点描写）」表記
- [ ] 購入メール・復元メールの文面と件名（敬語・リンク・送信元表示名）
- [ ] 特定商取引法に基づく表記・プライバシーポリシー（GA4/GTM の外部送信記載＝[analytics.md §6](analytics.md)）が存在しフッター等から辿れる

### §5. P3 計測と見え方（人間 約30分＋AI）

前提: GTM/GA4 コンソール設定（[phase-1-todo.md](phase-1-todo.md) ★・約1時間）が済んでいること。

- [ ] GA4 DebugView で3イベントの発火を目視: `tool_start`（メーカーを開く）／`generated_pdf`（書き出す）／`purchase`（テスト決済）
- [ ] サンクスページをリロードしても `purchase` が二重に飛ばない
- [ ] OG カード: X・LINE に TOP／商品／記事の URL を貼ってカード画像と文言が出る
- [ ] sitemap.xml と robots.txt が開け、atelier 等のオーナー用ページが載っていない
- [ ] Lighthouse（スマホ設定）を1回だけ流し、明らかな赤だけ拾う（点数は追い込まない）

### §6. AI に任せる範囲

| 分類 | 向いている仕事 | 具体例 |
|---|---|---|
| **Haiku 級**（安い・大量の「読む」仕事） | 照合・校正・食い違い探し | 誤字脱字／NG 語の文脈判定（grep 結果の白黒つけ）／価格 ¥200・¥980 や巻数 42 の表記ゆれ／alt・メタ記述の有無／FAQ と仕様の矛盾／メール文面の敬語 |
| **Claude Code**（Sonnet 級以上・「書いて動かす」仕事） | スクリプト作成と実行・自動チェック | リンク切れクロール／全ページの疎通（404・500 拾い）／ゲートの突破テスト（cookie 改ざん・未所有で書き出し API を叩いて拒否を確認）／公開42巻のデータ検品スクリプト／`tsc`・`next build` |
| **人間だけ** | 現物に触る仕事 | 実カード決済／メール受信と迷惑メール確認／紙への印刷／スマホ実機のタッチ／「子どもに出して気持ちいいか」の手触り |

既にある道具を使い回す: `/weekly-ops`（NG 語 grep 内蔵）・`web/scripts/check-ses.mjs`（SES 送信確認）・`web/scripts/recover.mjs`（購入復元の照会）・`web/scripts/test-gen.ts`（生成器チェック）。

依頼文テンプレ（Haiku 級への丸投げ用）:

```
web/app/ 配下のユーザー向け日本語文言を対象に、
①誤字脱字 ②「¥200」「¥980」「全42巻」「Lv.1〜5」と食い違う記述
③foundation/voice-tone.md §1 の NG 語（診断・処方 など）
を探して。修正はせず「ファイルパス・該当行・理由」の一覧だけ出して。
```

依頼文テンプレ（Claude Code への丸投げ用）:

```
localhost:3000 を起動して、sitemap.xml と主要導線から辿れる全 URL を
クロールして 404/500 と外部リンク切れを一覧にして。
続けて、所有 cookie なし・改ざん cookie の2パターンで
メーカーの PDF 書き出しゲートが拒否されることを確認して。
```

### §7. 進め方 — 2段階＋ブロック割

**段階1: テストモードで一巡**（本番 env 投入前の今すぐできる）

| ブロック | 中身 | 目安 |
|---|---|---|
| 1 | §2 P0 を紙→工房→復元の順で完走 | 2h |
| 2 | §3 P1（スマホ実機30分込み）＋ AI へ §6 の2テンプレを投げておく | 1.5h |
| 3 | §4 P2 の実印刷＋AI 結果の回収・修正指示、§5 のうち OG/sitemap | 1.5h |

**段階2: 本番化後の再走**（公開直前リハーサル・約1時間）

- 実カード ¥200 決済 → 受け取り完走 → 返金（§2 末尾）
- SES 実受信（フリーメール宛て・迷惑メール確認）
- Stripe Webhook 配信履歴・GA4 DebugView の3イベント

**公開判定: P0 が全部緑なら公開してよい。** P2・P3 の残件は公開後の週次ブロック（[../launch/operations.md](../launch/operations.md)）で拾う。

### §8. テストしないもの（受容済みの割り切り）

| 項目 | 理由 |
|---|---|
| webhook 重複によるメール2通 | 購入フローは DB を持たない MVP の受容済みリスク（低害）。※オンサイトメッセージの定義・計測だけは DynamoDB を使うが購入フローとは独立（[decisions.md §5.15](../decisions.md)） |
| 問題座標データのソフトゲート | 座標は商品ページで既にクライアント配信済み。認証 API 化は次フェーズ送り（checkout/success 冒頭コメント参照） |
| 負荷試験・E2E 自動テストスイートの整備 | 個人規模では費用対効果が合わない。手動＋使い捨てスクリプトで足りる |
| フォントの CDN 依存 | セルフホスト化は P2 運用開始後（[phase-1-todo.md §3](phase-1-todo.md)） |
