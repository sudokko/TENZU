# TSUMIKI（仮）兄弟サイト構築方針書

## サマリ

- **前提**: 第2サイト題材比較（→ [2026-07-07-second-site-tsumiki.md](2026-07-07-second-site-tsumiki.md)・18/18 本命）で確定した「積み木（四方観察・かぞえ）」を **TENZU の兄弟店**として建てる場合の方針書。着手トリガー＝TENZU ローンチ後・クロスセル MVP 完了・運用安定
- **位置づけ**: MISSION「空間認知の土台を持つ子を増やす」の直系第2店。TENZU＝**描く店**／TSUMIKI＝**頭の中で回して・かぞえて・うつしとる店**
- **境界規約**: 点格子の紙面に描くタスク＝TENZU、ブロック（ボクセル）を扱うタスク＝TSUMIKI。立体模写（斜投影の模写）は TENZU 残留
- **商品**: ローンチ3タスク（かぞえる／四方観察・選ぶ／四方図を描く）×外向け Lv 5段階×¥200 一律＝**11巻**。解答は層別分解図＝「解答も設計図」
- **D スコア（TSUMIKI 版・仮）**: `D = blocks + 3·hidden + 1.5·(layers−1) + 2·notch`。隠れブロックが最大ドライバー（立体模写 hiddenLines の再演）
- **メーカー**: ボクセル工房1種（積む→出題3タイプ自動生成）。触る無料＝小盤面／¥980 買い切り＝大盤面＋PDF 書き出し。実物積み木連動を差別化の物語に
- **技術**: TENZU 資産の**フォーク先行**（共通パッケージ抽出は2店舗安定後）。押し出しジェネレータ・atelier 検品・所有 cookie・maker-checkout・maker core を流用
- **ブランド**: rev.5 設計言語を家族継承（純白・Klee One）＋店舗識別＝点格子→**等角格子**。Voice/Tone・クリティカルコア「設計図ごと、全部公開する」・表現ガードレール全面継承
- **計測**: TENZU の残債（アタッチ率計測ゼロ）を教訓に、相互送客 UTM・工房アタッチ率をローンチ日から実装
- **未決（オーナー判断待ち3点）**: ①屋号確定・tsumiki.jp 空き確認 ②TENZU 立体模写 Lv4-5 の将来移管の要否 ③着手時の「兄弟店 vs 第10タスク」最終確認

## 詳細

### §1. 位置づけとブランドアーキテクチャ

**エンドースド・ブランド型の兄弟店**とする。TSUMIKI は独立屋号・独立ドメインだが、About・フッターで「点図形（点描写）プリント専門店 TENZU の兄弟店」を明示する。

- 明示する理由: ①個人運営の信頼を2店舗で共有できる ②相互送客の導線が自然になる ③「同じ思想（体系×全公開×紙とペン）の店」という物語が差別化になる
- 兄弟店にする理由（第10タスク編入としない理由）: 行為が「描く」から「かぞえる・選ぶ」へずれるため、「点図形（点描写）プリント専門店」の看板を薄めない。TENZU の専門特化性こそ競争力の源泉
- **境界規約（カニバリ防止の一次ルール）**: 「点格子の紙面に線を描く」タスクは TENZU の領土、「ブロック（ボクセル）の集合を扱う」タスクは TSUMIKI の領土。立体模写（斜投影を点格子に描く）は前者なので TENZU 残留。TSUMIKI の「四方図を描く」は方眼への正射影描画であり点格子模写ではない——境界はタスクの問いではなく**紙面形式**で引く
- 長期の家族マップ（構想のみ）: 迷路店（前段・年少〜年中）→ TENZU（年長〜小1）→ TSUMIKI（年長〜小2）。迷路店は比較で対抗（15/18）だった別スレッド

### §2. 屋号・商標・ドメイン

- 屋号: **TSUMIKI（仮・読み「つみき」）**。TENZU と同じくローマ字4-7文字・日本語一単語由来の型を踏襲
- 一般名詞ゆえの埋没リスクがあるため、**業態識別句を必須併記**: 「積み木（四方からの観察・かぞえ）プリントの専門店 TSUMIKI」。表記階層化は TENZU の「点図形（点描写）」型を踏襲＝主語「積み木」・副記「四方からの観察」（小受の分野名でもある検索語）
- 商標: TENZU 前例踏襲（[decisions.md](../decisions.md) 商標方針）＝**出願見送り・ドメイン取得のみ**。tsumiki.jp の空き確認が T0 タスク（取れなければ tsumiki-print.jp 等の複合、または屋号ごと再考）
- 固有 IP 参照は一切なし（TENZU 同様）

### §3. コンセプト・タグライン（仮3案）

ブランディングコンセプト（仮）:

> **見えないところを考える力を育てる、積み木（四方からの観察・かぞえ）プリント専門店。**

TENZU「考えながら書く力」との対応: TENZU は目と頭と手の連動（描く）、TSUMIKI は**見えない部分の心的補完と視点変換**（メンタルローテーション・パースペクティブテイキング）。学術裏付けは空間認知エビデンス（content/evidence.md）を共用できる。

タグライン候補（着手時に 3-way DR で確定・TENZU 第4世代の型を踏襲）:

- 案A（家族韻・三拍型）: 「**見て、かぞえて、たしかめる力を、積み木から。**」
- 案B（コア価値直球）: 「**見えない積み木を、かぞえられる子に。**」
- 案C（行為の翻訳）: 「**頭の中で、積み木がまわる。**」

表現ガードレール: TENZU voice-tone.md を全面継承（煽らない・診断語彙 NG・「入学までに」型時間軸煽り禁止・課題性質フレーミング）。追加 NG 候補: 「IQ」「天才」訴求（積み木ジャンルは市販ドリルにこの語彙が多く、同調すると V1 违反）→ 着手時に voice-tone へ追記。

### §4. ターゲット・市場

- **主戦場: TENZU と同一＝就学前後（年長〜小1）**。ただし重心はやや上（かぞえ Lv 上位・四方図は小1〜小2が自然）。フランク＝年中（かぞえ Lv1-2）／小2〜小3（Lv4-5）
- 受動拾い: 小受「四方からの観察」対策層（頻出分野・語り分けレイヤーで対応、旗艦にしない）／中受図形の早期準備層／療育・OT 文脈（視空間）
- 競合観（比較調査より）: 天才ドリル立体王・ピグマリオン・こぐま会＝**同志（引用先）**。無料プリント＝あるが体系なし。ボクセル工房＝前例なし
- 検索面の中核クエリ群: 「積み木 数える 問題」「四方からの観察 教え方/プリント」「空間認識 鍛える プリント」「見えない積み木」

### §5. 商品設計（タスク体系・ラダー・解答様式）

#### §5.1 タスクファミリー（7種・ローンチ3種）

| タスク（仮称） | 問い | 3群 | ローンチ |
|---|---|---|---|
| かぞえる | ぜんぶで何個？（見えない分も） | かぞえる力 | ◎ T1 主力 |
| 四方観察・選ぶ | まえ/よこ/うえから見るとどれ？ | 見え方をつかむ力 | ◎ T1 |
| 四方図を描く | 上から見た形を方眼に描く | うつしとる力 | ◎ T1 |
| 同じかたち | 回すと同じになるのはどれ？ | 見え方をつかむ力 | T2 |
| ふやす・へらす | A を B にするには何個？ | かぞえる力 | T2 |
| 分解 | どの2つでできている？ | 見え方をつかむ力 | T2 |
| 影・断面 | —（構想のみ） | — | 未定 |

3群ピル（かぞえる力・見え方をつかむ力・うつしとる力）は TENZU CoverageStudio の3力ピル型を踏襲。TENZU の教訓「まず作りきる」に従い、**T1 は3タスクに絞る**（TENZU は9タスク同時で作りきりが最長工程になった）。

#### §5.2 レベルラダー（外向け Lv 5段階継承・Vol で細かさ吸収）

| Lv | ブロック数 | 層 | 隠れ | 形の性質 |
|---|---|---|---|---|
| Lv.1 | 〜5 | 1〜2 | 0 | 平積み・一列 |
| Lv.2 | 〜8 | 2 | 0 | 直方体系・全部見える |
| Lv.3 | 〜12 | 2〜3 | 1〜2 | 段差・はじめての「見えない」 |
| Lv.4 | 〜18 | 3 | 3〜5 | L字・門・凹み |
| Lv.5 | 〜27 | 3〜4 | 6+ | 複合形状・視点統合 |

#### §5.3 D スコア（TSUMIKI 版・仮）

> `D = blocks + 3·hidden + 1.5·(layers−1) + 2·notch`

- `hidden`＝完全に隠れたブロック数（最大ドライバー・立体模写 `+3·hiddenLines` の再演）／`notch`＝凹み・張り出し数
- 巻構造は模写の型を踏襲: **巻＝Lv 窓（隠れレジーム）／巻内＝D 昇順**
- 係数は仮置き。生成→atelier 目視検品→較正のループで確定（D スコア再校正と同じプロセス）
- 四方観察タスクは選択肢設計も難易度因子（ダミー肢の紛らわしさ＝鏡像/1個違い）→ 検品時に別途 `distractor` 補正を検討

#### §5.4 解答様式＝「解答も設計図」

- **かぞえる**: 層別分解図（1段目/2段目/3段目を分けて描き、段別個数＋合計を明記）。機械生成可能で、クリティカルコア「設計図ごと、全部公開する」が解答紙面にまで貫通する
- **四方観察**: 正解面ハイライト＋「どうしてそう見えるか」1行（Pillar P4 言語化の継承。親の声かけ文化を解答に埋め込む）
- **四方図を描く**: 完成図＋よくあるまちがい1点（「見えない列を描き忘れる」等）

#### §5.5 SKU 初期構成（T1＝11巻・各12〜15問・¥200 一律）

- かぞえる Lv.1〜5＝5巻／四方観察・選ぶ Lv.2〜4＝3巻／四方図を描く Lv.3〜5＝3巻
- メタデータ厳選公開（D・ブロック数・隠れ数・層）＝TENZU と同じ「中身が見える」棚

### §6. メーカー（ボクセル工房）

- **1種のみ**: ボクセルエディタ（タップで積む・消す）→ 同一のボクセル配置から「かぞえ／四方観察／ふやすへらす」の出題タイプを切り替えて自動生成。TENZU の「10メーカー」ではなく「1工房×出題タイプ」構成＝開発・UI 圧縮
- ゲート: **触る無料**＝画面内で積んで遊ぶ・小盤面（3×3×3）／**¥980 買い切り**＝大盤面（5×5×5）＋PDF 書き出し（TENZU §4.6 PDF ゲート＋模写グリッドゲートのハイブリッド型）
- UI 資産流用: maker core・消しゴムモード・quickbar（スマホ圧縮）・保存済み編集・完了画面レコメンド
- **実物積み木連動**を工房の物語にする: 「おうちの積み木でつくる → 紙でかぞえる → 崩してたしかめる」。「書く学習は紙とペン」RTB の積み木版＝「たしかめる学習は実物」

### §7. 価格・無料方針

- ¥200 一律・都度買い・カート（TENZU 完全踏襲・pack-commerce の思想）
- 無料3層の継承: **見る**（サンプル閲覧プレビュー）／**触る**（工房 小盤面）／**試す**（¥200 単品）。**配る無料（独立無料 PDF）は置かない**
- 記事内サンプル例外（文脈付き1-3問）も継承

### §8. 技術・実装方針

#### §8.1 資産流用マップ

| TENZU 資産 | TSUMIKI での扱い |
|---|---|
| Python 押し出しジェネレータ＋法線隠線判定 | ボクセル版へ拡張（隠れブロック判定に転用・コア流用） |
| SolidPaperSVG・斜投影（キャビネット）描画 | 見取り図面としてほぼ直流用 |
| 正射影レンダラ（四方図） | 新規・軽量（ボクセル→2D 方眼投影） |
| atelier 検品（ladder.json / catalog・schema v2） | `voxels` フィールド追加で流用 |
| 所有 cookie・maker-checkout・PDF HMAC ゲート | そのまま流用 |
| maker core（共通化済） | ボクセル工房のベース |
| D 較正プロセス（生成→検品→係数調整） | プロセスごと流用 |
| rev.5 tokens・PDF 出力パイプライン | フォーク＋店舗識別差し替え |
| Stripe（price_data 直書き）・SES・MailerLite | 同一アカウント・設定分離（商品名プレフィックス等） |

#### §8.2 リポジトリ戦略＝フォーク先行

- **推奨: TENZU repo をフォークして tsumiki repo を新設**。モノレポ化・共通パッケージ抽出は**しない**（2店舗が安定してから判断）
- 理由: ①個人運営＋AI 開発では、共有パッケージの同時リグレッションが最大リスク ②maker core 抽出の実績があり「共通化は後からでも可能」と実証済み ③TENZU 側のローンチ運用を絶対に止めない
- 同期ポリシー: セキュリティ修正のみ手動で相互反映。機能は独立進化を許容

#### §8.3 インフラ

- 別 Amplify アプリ・別ドメイン・同一 AWS アカウント。SES は TENZU で**サンドボックス脱出済みの状態を前提**にできる（本番化残務が先である理由のひとつ）
- Stripe 同一アカウント（レポート上の店舗区別は metadata / 商品名プレフィックスで）

### §9. 集客・SEO・相互送客

- コンテンツ: pillar 1本（例「積み木遊びと空間認知——『見えない積み木』がかぞえられるということ」）＋クラスタ（四方からの観察の教え方／かぞえ間違いの典型パターン／実物積み木の選び方）。evidence.md の空間認知エビデンスを共用し、TSUMIKI 固有の追加調査は最小限に抑える
- SEO 例外ルール継承: 小受クエリはクエリ引用のみ・H1 前面化しない（「高校受験」ルールの積み木版＝「小学校受験」を title/H1 に前面化しない）
- **相互送客（クロスセル MVP の教訓を初日実装）**:
  - TENZU 立体模写・分解の商品ページ→TSUMIKI バナー（onsite-messaging の「生涯1回・モーダル禁止」原則継承）
  - TENZU 購入者への MailerLite 1通（開店告知・クーポンではなく「使い分けガイド」訴求）
  - TSUMIKI 側フッター/About→TENZU
  - **全導線に UTM・アタッチ率計測をローンチ日から**（TENZU で後回しにした残債を繰り返さない）
- Pinterest: TENZU 3ヶ月パイロットの結果を見てから判断（独立パイロットはしない）
