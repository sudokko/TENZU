# note 開発実録連載 執筆 craft

## サマリ

- 対象: **オーナー個人 note の開発実録連載**「営業マンがAIと4ヶ月で"点描写プリント専門店"を作った話」全5回＋続編（収益報告）。TENZU 公式記事（MDX 16ページ体系）とは**別枠**
- 原稿の置き場所: Notion「副業プロジェクト＞連載マップ」配下に下書き → note へ手動投稿（投稿時チェックリストは連載マップ側）
- スタンス = **実録＋目標宣言型**: 売上ゼロ・ローンチ前を冒頭で開示。**起きていないことは書かない**（§2）
- 屋号は実名＋リンクあり・当面全部無料（オーナー決定・[decisions.md](../decisions.md) 外の連載固有決定として本書が SSOT）
- 各回の型: あらすじ→「この回でわかること」→本文→まとめ→次回予告→連載フッター（§3 にスケルトン）
- 文体: です・ます・一人称「私」・煽らない・1回 3,000〜4,500字（§4）
- 各回に**一般化できるノウハウを2〜4個**入れる（TENZU の宣伝でなく読者の持ち帰り物）
- TENZU 実名を出すため **[voice-tone.md](../foundation/voice-tone.md) §1 の NG 語彙・効果断定 NG を全面適用**（個人 note でも免除しない）
- note 貼り付け互換: **表を使わない・見出しは `##` の1階層のみ・画像は【画像①: 内容／alt: 文】マーカー**
- 数字・日付・史実は執筆のたびに一次ソースを開いて確認（§5 参照表。本書に値は書かない）
- 公開前検証は3点セット: NG語彙 grep／数字突合／note互換 grep（§6・機械実行可能）
- 文体見本 = 公開済み5本（附録リンク）。迷ったら第1回と第4回を見る
- **高性能モデル以外で書くときは §7 の5工程分割に従う**（一発書きさせない・事実は参照表からのみ・創作禁止を明示）

## 詳細

### §1. 連載の性格

- 語り手はオーナー個人（店主）。TENZU 公式の三人称 note 運用（[channels.md §2.5](../acquisition/channels.md)＝月1・思想まとめ）とは**別人格・別アカウント枠**。ただしブランドに跳ねるため Voice 制約は共有する（§4）
- 連載の行動原理はクリティカルコア「設計図ごと、全部公開する」（[brand.md §0.5](../foundation/brand.md)）の商売版セルフ適用。「店の設計図を公開する店主が、商売の設計図だけ隠すのは筋が通らない」が一貫性の芯
- 位置づけは [operations.md §4](../launch/operations.md) の「note 月1（B3 の月1追加枠）」。B2 の TENZU 公式記事より優先度は下
- 想定読者: AI を使って何か作って売ってみたい会社員／副業で小さく始めたい人／デジタル教材・PDF 販売に興味がある人。**点描写の見込み客ではない**（見込み客向けの語彙・訴求は公式記事の仕事）

### §2. スタンスの規律（実録＋目標宣言型）

1. **起きていないことは書かない**。売上・顧客の反応・効果実感など未発生の事実は、目標・計画・仮説として書く。成功譚の先取りは連載の信用ごと壊す
2. **願望と計画を区別して両方見せる**。公式の数値計画（基準線）と野心目標を並記し、差分を「レバー」（何が上振れ要因か）で説明する。数字を1つに丸めない
3. **失敗・撤回・方針転換は隠さず、学びの形で書く**。「作って捨てた」は本連載の主力コンテンツ
4. **数字・日付・固有名詞は一次ソース突合必須**（§5）。記憶・雰囲気で書かない
5. 各回の冒頭で連載の前提（ローンチ前・売上ゼロ・全記録公開）を毎回3行で再掲する。単独回から読まれる前提

### §3. 各回の構成テンプレ

コピペ用スケルトン（`<>` を埋める）:

```markdown
# <タイトル: 数字か具体的フックを含む・煽らない>

## 前回までのあらすじ（第1回のみ「この連載について」）

<前回の要点1〜2文＋連載の前提3行（第n回・ローンチ前・売上ゼロ・全記録公開）>

この回でわかることは、次の<2〜4>つです。

- <読者ベネフィットで書く（「〜した話」「〜の考え方」）>

## <本文見出し（## 基本・3〜6個・「話の転換点」で切る。4,500字超の長編は ### の小見出しを併用可＝note の許容は2階層まで）>

<本文>

【画像①: <何のスクショ/図か>／alt: <alt 文>】

## まとめ — <この回の持ち帰り>

<箇条書き2〜4点。各点は太字リード＋補足1文>

<次回予告1段落（次回の問いを立てる）>
```

- 分量は 3,000〜4,500字。超えるなら回を割る（例外: オーナーが「1本で長く」と指定した2段構成回は 6,000字程度まで可・### 小見出しで章分け）
- 画像は1回 1〜2枚。マーカーのみ置き、実画像はオーナーが投稿時に挿入
- 「ためになる」の作り方: 各回のノウハウは**点描写・TENZU を知らなくても使える抽象度**まで一般化してから書く（例:「マイページ廃止」→「機能の名前が体験を決める」）

### §4. 文体・語り・タブー

**文体**
- です・ます調。一人称「私」。断定は事実にだけ使い、見込みは「〜と考えました」「〜のはずです」
- 煽らない・叫ばせない（ブランド V1 を連載にも適用）。「！」の連発・恐怖訴求・時間切迫の煽りは使わない
- 語り手プロフィールの定型: 「元 SE（3年）→ 営業12年 → 事業開発。コードから10年以上離れた43歳の会社員・2児の父」。**「非エンジニア」と自称しない**（元 SE なので不正確）
- 時点を明示する: 「この文章を書いている○月時点」形式。投稿時に調整する前提で書く

**タブー（TENZU 実名を出すため全面適用）**
- [voice-tone.md §1](../foundation/voice-tone.md) の NG 語彙 grep 対象すべて（処方箋・弱点診断・手遅れ・差がつく・克服 等）
- 教育効果の断定 NG。「図形の感覚や字形をとらえる力の土台になる**と言われています**」の距離感まで
- 競合を実名で下げない。無料サイトへの言及は「検索1位の大手サイト」等の匿名＋敬意（量と網羅性は本物、と立てる）。市販ドリル（こぐま会・ピグマリオン等）は同志ポジションの文脈でのみ実名可
- 点つなぎを下に見る表現 NG／屋号の語源ネタは書かない（IP 配慮）／TENZU のツールを「アプリ」と呼ばない（Web ツール・工房）
- TENZU 初出は「点図形（点描写）プリントの専門店 TENZU（てんず）」の並記形

**名物**
- AI の発言引用は journal の実録からそのまま使ってよい（例: 第1回の「正直に言うわね」）。初出時は「（口調はこういう設定にしてあります）」の一言を添える

### §6. 公開前検証3点セット（機械実行）

1. **NG 語彙 grep**: [voice-tone.md §1](../foundation/voice-tone.md) の grep パターン全文＋本連載の追加分 `診断|鍛え|修行|特訓|アプリ|頭が良く|伸びる|効果がある` を原稿に対して実行し、ヒット0を確認（「教材アプリにはしなかった」のような否定文脈のみ目視で許容判断）
2. **数字突合**: 原稿中の金額・件数・割合・日付をすべて抜き出し、§5 の一次ソースと照合
3. **note 互換 grep**: `^\|`（表）と `^####`（4階層見出し）がヒット0（見出しは ##/### の2階層まで）／画像が【画像①: ／alt: 】形式／連載フッターが最新のリストか

### §7. 高性能モデル以外で書くときの運用（工程分割）

一発で「記事を書いて」と頼まない。**5工程に分け、各工程の出力を人間が確認してから次へ渡す**。

1. **素材抽出**: 対象の journal EP（ファイルパス指定）と §5 の該当 SSOT を読ませ、「事実・日付・数字・引用候補」の箇条書きだけ出させる。プロンプトに「**ファイルにない出来事・会話・感情は書かない（創作禁止）**」を明記
2. **構成**: §3 のスケルトンを渡し、見出しと各節の要点1行だけ埋めさせる。ここで人間が回のネタ配分を確定
3. **執筆**: 承認済み構成＋工程1の素材リスト＋§4 のタブー全文＋**文体見本1本**（附録の第1回か第4回を丸ごと貼る）を渡して本文化。節ごとに書かせると崩れにくい
4. **検証**: §6 の3点セットを実行させる（grep はコマンドとして実行。モデルの目視に頼らない）
5. **仕上げ**: タイトル・「この回でわかること」・まとめの3点が本文と一致しているか突合させ、ズレは本文でなくリード側を直す

迷いどころの既定値（モデルに委ねない）: 長さ4,000字前後／画像1〜2枚／「わかること」とまとめは各3点／ノウハウの抽象化は「TENZU を知らない読者に通じるか」で判定。
