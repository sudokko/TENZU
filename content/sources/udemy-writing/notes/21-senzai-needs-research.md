# 21. ライティング学習のキーワードリサーチと潜在ニーズ分析

分類: 要確認→抽出（構成提案の読者理解原則として structure-craft.md 行き）

## 主張（このテーマの核心 1-3 行）

キーワードそのものではなく「そのキーワードで検索している人がどんな状況・段階にいるか」を周辺情報から絞り込むのが本質。顕在ニーズ（言葉になっている疑問）だけでなく、検索者がまだ言語化していない潜在ニーズ（先回りすると喜ばれる情報）を、実在の質問・悩みの観察から発掘し、構成に織り込む。自分の想像で読者像を決めると外れる——実在データで先入観を裏切られるのが正しいプロセス。

## 技術・ルール

1. **検索者の段階を最初に判定する**: テーマに着手する前に「この読者はすでに実践している人か、これから始めたい人か」を判定する。例として「○○ 勉強」で調べるのは従事者ではなく未経験〜入門期の人。記事の前提知識量・語り口・構成順はこの段階判定で決まる。
2. **共起する関心語から人物像を絞り込む**: 同じテーマの読者が他にどんな語と一緒に調べているか（資格・費用・無料・やり方・おすすめ・初心者…）を並べて眺め、「どういう人がこのテーマを調べているのか」の像を段階的に絞る。個々の語に答えるのではなく、語の集合から状況を読むのが目的。
3. **「無料」「やり方」系の語は読者の制約条件のシグナル**: お金をかけたくない・自力で進めたい等の制約が見える。構成では無料／低コストの選択肢や自宅でできる方法に触れると、明示されていない期待に応えられる。
4. **顕在ニーズと潜在ニーズを分けて扱う**: 顕在＝検索語に表れている疑問（まず本文で正面から答える）。潜在＝読者自身がまだ気づいていないが、知ると「それが知りたかった」となる情報。記事は顕在に答えた上で潜在を先回りして差別化する。
5. **潜在ニーズは「実在の質問・悩み」の観察から拾う**: Q&A 的な場で実際に飛び交っている疑問を眺め、(a) どんな質問が繰り返されるか (b) 質問文の背景情報（年齢・立場・状況）に何が書かれているか、をメモする。操作手順ではなく「生の悩み文を読む」こと自体が手法。
6. **質問の背景文こそ読み込む**: 質問本文より「20代後半・将来は副業にしたい・収入が上がらない・初心者向け講座を探している」のような自己紹介部分に状況・動機・不安が凝縮されている。ここから「なぜそれを知りたいのか」を推定する。
7. **繰り返し出る悩みパターンを赤字級（最重要）として束ねる**: 集めたメモを整理し、頻出する質問タイプ（例: スクール・本・資格で「まず学びの入口を整えたい」、仕事の取り方が分からない、評価は得たのに次につながらない…）をグルーピングする。頻度の高い束＝構成の主要見出し候補、低頻度の束＝補足セクションか割愛。
8. **「行動の典型順」を読み取って構成順に写す**: 観察から「まず本を読む→資格を考える→スクールを探す」のような読者の典型的な行動順序が見えてくる。記事の見出し順は読者のこの自然な順序に沿わせる。
9. **想像と実データのギャップを必ず確認する**: 講師自身「10代が多いと思ったら、実際は大学生〜20-30代前半・主婦層が多かった」と先入観が外れた。読者像は想像で固定せず、実在の声で年齢層・立場・動機を補正してから書く。
10. **意外な読者セグメントの存在をメモしておく**: 主読者と違う層（例: 個人ではなく企業の担当者が調べている可能性）に気づいたら、主構成は崩さず一言の言及や FAQ で拾えるか検討する。
11. **「いい質問」を見つけたら構成の問いに転用する**: 「基礎は理解したがその先どう勉強すればいいか」のような、検索語には表れにくいが切実な問いは、そのまま H2/H3 の問い立てとして使える価値がある。

## 具体例・Before/After

- **段階判定の例**: 「(分野名) 勉強」という検索語だけだと幅広く見えるが、共起語（初心者・費用・講座・資格・無料）を並べると「これから始めたい人」が検索していると判明。→ 既従事者向けの応用記事ではなく、入門者の最初の一歩に寄り添う構成にすべき、と方針が決まる。
- **背景文からの推定例**: 「評価は高いのに仕事が来ない」という悩み投稿から、「学び方」だけでなく「やり方・続け方に迷う段階がある」という潜在テーマを発見。検索語には出てこないが記事に入れる価値がある論点。
- **読者像の補正例**: 講師は若年層中心と予想していたが、実際の質問者は大学生・主婦・20-30代前半が中心で、「在宅で働けること」への魅力が動機として頻出。→ 訴求軸と例示を在宅・両立文脈に寄せる修正が入る。
- **行動順の例**: 質問群を整理すると「本→資格→スクール」の順で入口を探す人が多いと分かり、その順で情報を提示すれば読者の頭の中の順序と一致する。

## TENZU 適用メモ

| 技術 | 判定 |
|---|---|
| 1. 段階判定 | **そのまま使える**。記事リスト確定済みでも「この記事の読者は点描写を始める前か、つまずいた後か」の判定は構成提案の第一歩。personas.md（P-公文-a／P-知育-a/b／受動拾い P3-a 等）と clusters.md の検索意図でほぼ即決できる |
| 2. 共起関心語から人物像 | **そのまま使える**（縮小適用）。キーワード選定工程は不要だが、確定テーマの周辺語（「点描写 効果 何歳」「できない」等）を眺めて読者の状況仮説を立てる用途は有効。keyword-research.md の既調査データを再利用すればよく、新規ツール調査は不要 |
| 3. 制約条件シグナル（無料・やり方） | **そのまま使える**。TENZU 読者の制約は「家庭で・印刷機で・無理なく・低単価」。無料系クエリは記事ではなくおためし点描写メーカー／サンプルPDF へ受け渡す設計（clusters.md §1.5 の取引意図分離）と整合 |
| 4. 顕在/潜在の二層 | **そのまま使える**。結論先出しルールと相性が良い：顕在ニーズへの答え＝冒頭の結論、潜在ニーズ＝本文後半の先回り情報、と層が対応する |
| 5. 実在の悩み観察 | **そのまま使える**（手段は置換）。Yahoo知恵袋の操作手順ではなく「親の生の悩み文を読む」原則として採用。TENZU では知恵袋・SNS の「点描写 できない」「図形が苦手」系投稿の観察が相当。ただし煽り素材化は NG、共感の解像度を上げる目的のみ |
| 6. 背景文の読み込み | **そのまま使える**。「年中・公文に通っている・斜めの線でつまずく」のような背景情報が記事のレベル言及・年齢帯記述の精度を決める。ただし年齢帯は広く重ねる（傷つきにくさ原則）ため、特定年齢を断定的に書かない点で運用調整 |
| 7. 頻出悩みのグルーピング→見出し化 | **そのまま使える**。構成提案時の H2 候補の優先順位づけにそのまま転用 |
| 8. 行動の典型順＝見出し順 | **TENZU ルールと一部衝突**。読者の探索順に沿うのは有効だが、TENZU は結論先出しが上位ルール。「結論→読者の行動順で詳細展開」のハイブリッドで適用（行動順を記事全体の骨格にし、各節は結論先出し） |
| 9. 想像と実データのギャップ補正 | **そのまま使える**。ペルソナ確定済みでも「ペルソナの再検証」ではなく「このテーマでのペルソナの温度感確認」として軽量適用。案H' でターゲット全面見直しが起きた経緯とも整合する教訓 |
| 10. 意外なセグメントの拾い方 | **そのまま使える**。TENZU の「受動拾い」（P4 療育・P5 教員等）の運用と完全一致。主構成は中核向け、受動層は FAQ・一言言及で迎え入れる |
| 11. いい質問の H2/H3 転用 | **そのまま使える**。ただし問い立ての語彙は表現置換ルール準拠（「診断」「弱点」NG → 「次の一手」「戻り道」）。voice-tone.md §1 の SEO 例外（冒頭のクエリ引用のみ許容）も併用 |
| （講座内に散見される「資格・スクールで稼げる」式の期待喚起ニュアンス） | **不適用**。煽り・期待インフレは TENZU 誠実トーンと衝突。悩みは観察対象であって増幅対象にしない |
