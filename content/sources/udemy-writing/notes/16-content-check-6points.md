# 16. ウェブライティング実践編：コンテンツチェック6つのポイント

分類: 抽出C（推敲系 → revision-craft.md 行き）

## 主張（このテーマの核心 1-3 行）

公開前チェックは2層で行う。①内容チェック（読者の知りたいことに応えたか・読者の生活が良くなるか・読者がゴールを達成できるか）、②SEO チェック6項目（タイトル／メタディスクリプション／URL／見出し階層／画像 alt／リンクテキスト）。書いているうちに軸がズレるのが常態なので、書き終わってから必ず最終チェックする。

## 技術・ルール

### 内容チェック（SEO チェックの前段・3観点）
- 公開前に「①読者の知りたいことが書けているか ②読者の生活の質が向上する内容か ③読者は記事のゴールを達成できるか」を書き終えた後に再確認する。執筆中に軸がブレて「自分の書きたいこと」に流れる事故は構成済みでも起こるため、最終チェックは省略しない

### SEO チェック6項目（公開前・順番固定）
1. **ページタイトル**: ①ターゲットキーワードを入れる ②32〜37文字以内 ③重要なキーワードほど左側（先頭側）に置く
2. **メタディスクリプション**: ①ターゲットキーワードを入れる ②120文字以内でページ内容を正確に要約（超過したら文字カウントしながら削る）③全ページ固有のものを書く（使い回し禁止・記事公開ごとに毎回個別設定）
3. **URL（パーマリンク／スラッグ）**: ①記事内容を表す英単語・半角英数字で書く ②短く端的に、狙うキーワードの直訳が分かりやすい ③区切りはアンダースコアではなくハイフン ④日本語スラッグは検索エンジンが内容を読めないので使わない
4. **見出しタグ階層**: ①h1=記事タイトル1個、本文は h2 から使う ②階層を飛ばさない・入れ子を崩さない（h3 は必ず h2 の中、h4 は必ず h3 の中。h2 の直下に h4 が来たらアウト）③見た目の強調目的で見出しタグを使わない
5. **画像**: ①ファイル名は内容が分かる端的なものにする ②全画像に alt（代替テキスト）を設定する。alt は画像を一言で説明する文 ③alt にキーワードを詰め込まない ④全画像に同じ alt を使い回さない（その画像をその位置で使った意図が伝わる説明にする）
6. **リンク（アンカーテキスト）**: ①「こちら」「クリック」等の曖昧テキストにリンクを貼らない ②リンク先の内容が分かるテキスト（「○○に関する△△動画」等）に貼る。検索エンジンはアンカーテキストでリンク先を理解する ③読者にとって有益なサイトにのみ外部リンクを貼る

## 具体例・Before/After

- メタディスクリプション: 書いた初稿が137文字 → 文字カウントしつつ削って114文字に収めてから設定する、という推敲手順の実演
- パーマリンク: 狙いキーワードが「ライティング 勉強」の記事に対し、`writing-how-to-study` のような「短い英単語をハイフンでつないだ直訳スラッグ」を設定。「勉強法」と日本語のままにすると検索エンジンが内容を認識できない、という対比
- 見出し: 目次で「h2 が6本、3本目の h2 の中に h3 が4本」という構造を確認し、「h2 の直下に h4 が来ていたら構造として間違い」と判定する例
- alt: 「Mac・ノート・ペン・コーヒー」の素材写真に、記事テーマと無関係な汎用 alt ではなく、付随する見出し（ライター人材の話）に沿った説明を付け直す例。全画像同一 alt は不自然と指摘
- アンカーテキスト: 「この動画」というリンクを「○○の Web ライティングに関する YouTube 動画」に書き換え、リンク先が何かをテキスト自体で伝わるようにする Before/After

## TENZU 適用メモ

- **内容チェック3観点**: そのまま使える。TENZU 記事の「読者のゴール」=「親が次の一手（レベル・種類・始め方）を決められること」に読み替えて公開前チェックリスト化
- **タイトル最適化（KW・32〜37字・左寄せ）**: そのまま使える。ただし「高校受験」をタイトル前面化しない既存ルール（MEMORY/voice-tone）が優先。煽り型タイトルにしない範囲で KW 左寄せを採用
- **メタディスクリプション120字・固有設定**: そのまま使える。Next.js では `metadata.description` で記事 MDX ごとに固有設定（WordPress プラグイン手順は不要・思想のみ採用）
- **パーマリンク英語ハイフン区切り**: そのまま使える。既に `content/urls.md` でスラッグ設計済み（「点描写」系は tenbyosha 等の方針あり）なので、衝突時は urls.md が SSOT として優先
- **見出し階層 h2→h3→h4・強調目的禁止**: そのまま使える。MDX テンプレ（content/templates.md）のリント観点に追加候補
- **画像 alt（端的・固有・詰め込み禁止）**: そのまま使える。TENZU はサンプル図版・SVG が多いので「Lv・タスク種類が分かる alt」を標準化すると効果大。装飾 SVG は alt 空でよい（講座は触れていないが Web 標準として補足）
- **アンカーテキスト最適化・「こちら」禁止**: そのまま使える。TENZU の誠実トーンとも整合（リンク先を明示する方が読者に正直）。現状 `href="#"` 未配線箇所の配線時に適用
- **「検索順位を最大化」目的のキーワード詰め込み方向への拡大解釈**: 不適用。講座自体も詰め込み NG を明言しており、TENZU では voice-tone の NG 語彙（診断・処方箋系）チェックを SEO チェックに必ず併走させる
