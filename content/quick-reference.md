## サマリ

- **用途**: 執筆セッションの立ち上げ高速化。ルール本体を全ファイル通読しなくても、この1枚で「書き出せる」状態にする思い出し用チートシート
- **非SSOT**: 定義の正は常にリンク先（[voice-tone.md](../foundation/voice-tone.md)・[templates.md](templates.md)・craft 3冊）。**本ファイルと食い違ったら SSOT が正**・気づいたら本ファイルを更新する

- 迷ったら入口索引 [article-writing-kit.md](article-writing-kit.md) へ戻る

## 詳細

### §1. 工程と鉄則

```
企画(clusters §1.5 記事化可否) → dump(オーナー) → 構成提案(AI) → 構成確定(オーナー)
→ 本文化(AI) → article-reviewer → 推敲(表現レベルのみ) → オーナー仕上げ
```

- **「足さない」三層**: dump/メモに無い**主張・事実・数値・引用**を、構成でも本文化でも推敲でも足さない。足りなければ `【ギャップ: …】`【要確認: …】で明示（[structure-craft.md §2](structure-craft.md)／[writing-craft.md §2](writing-craft.md)／[revision-craft.md §2](revision-craft.md)）
- **H2/H3 はオーナー確定事項**。AI は文言・順序・階層を変えない
- 推敲は本文化と**別パス**で行い、変更点リストを必ず添える
- 語り手: 「専門家が上から教える」ではなく「**同じ親として先に気付いた立場**」。主語は「TENZU では…」（記事内で「私」は使わない）

### §2. 表記・用語早見

| ルール | 内容 |
|---|---|
| 表記階層化 | H1・屋号紹介＝**「点図形（点描写）」並記**／H2以降の概念語＝「点図形」優先／SKU・カテゴリ・URL・meta＝「点描写」維持 |
| F3 公式訳 | 「空間認知」の初出は必ず「**空間認知（＝形の向き・位置・大きさをとらえる力）**」と併記（記事H1直下・FAQ初出は必須）。接続は「とらえる/育てる/広げる」（「鍛える/磨く」NG） |
| 認知/認識 二刀流 | ブランド軸・本文＝**空間認知**固定。「空間認識」を H1 に使えるのは **C4-2 と L-2 のみ**（本文1段目で「教育心理学では『空間認知』」へブリッジ必須）。「TENZU は空間認識を…」型は禁止 |
| 図形の基礎力/空間認知 | フロント（Hero・広告・CTA・OG）＝「**図形の基礎力**」／学術 RTB（記事 H2-2 以降・PR・LLMO）＝「**空間認知の土台**」／橋渡しは「図形の基礎力＝空間認知の土台」両方併記 |
| descriptor | 「TENZU」単独表示禁止。「**点描写プリント専門店 TENZU**」等の日本語 descriptor セット運用 |
| 4群の名前 | 顧客接点は動詞ベース: **見て写す／かたちを動かす／重ねる・分ける／立体でとらえる**（「観察/変換/構成/立体」は内部語） |

### §3. NG→OK 置換（統合表）

| カテゴリ | NG | OK |
|---|---|---|
| 医療メタファー | 処方箋／特効薬／治療／弱点診断／健康診断／自己診断／穴を埋める | 練習プラン／次の一手／戻り道／**レベル選びガイド**／抜けを補う |
| 時間軸の煽り | ○年生で差がつく／手遅れ／もう間に合わない／小1の壁 | いつからでも戻れる／今の地点から始める |
| 修行・道場 | 鍛える／特訓／克服／習得／叩き込む／○級・○段／マスター | 育てる／身につける／慣れる／Lv.X 到達 |
| 予防→拡張 | つまずかないために／苦手にならないように／やっておかないと後悔 | 図形を頭の中で自由に動かせるように／○○の土台になる／支える／広げる |
| 啓蒙の飛躍 | 点描写をやれば算数が伸びる | 視覚空間スキルは算数達成と関連することが複数の研究で示されています |
| 点つなぎ | 点つなぎでは物足りない／卒業しよう | 点つなぎを楽しんだ後に／点つなぎの次に、点描写を |
| 欠陥→特性 | 斜め線が描けない子／集中力がない | 斜め線がまだ難しい段階のお子さん／短時間集中で力を発揮するタイプ |
| 誇張・断定 | 劇的に／必ず／100%／集中力が伸びる／発達に効果 | 段階的に／研究では〜と報告／形の向き・位置・大きさをとらえる練習 |
| お店路線 | 教える・指導する（主動詞）／先生・コーチ／修了証 | お渡しする・ご紹介する／店主・点描士 |

### §5. フロントマター雛形（SSOT: [templates.md §2](templates.md)）

```yaml

slug: mitorizu-drawing            # urls.md の確定スラッグ
title: …                          # H1（点図形（点描写）並記ルール確認）
description: …                    # 80-120字・「点描写」厚め
parent_pillar: pillar-c           # pillar-a|b|c|d|none（Pillar 自身は none）
parent_category: symptom-solve
target_persona: [P2b, P4]         # 先頭=主
target_level: [Lv.2, Lv.3]

target_skus: [S07]                # 1-3本・空配列可
updated_at: 2026-07-02
phase: phase-2                    # phase-1=仕込み(SKUカード非表示)|phase-2|phase-3
cta_mode: sku-full                # 固定

```

### §6. 記事の型と CTA 強度（SSOT: [templates.md §3-§4](templates.md)）

11 セクション: ①リード(120-180字) ②目次 ③**結論先出し TLDR**(3-5行・各40字以内・根拠1行) ④背景 ⑤中核解説 ⑥実践・段階 ⑦InlineCTA ⑧注意点・FAQ ⑨SKUカード ⑩関連3本 ⑪参考文献

| article_type | CTA 強度 | 字数 | 省略可 |
|---|---|---|---|
| pillar | weak | 5000-7000 | ⑨ |
| cluster-howto | mid | 2500-4000 | ⑪ |
| cluster-symptom | strong | 3000-5000 | なし |
| cluster-compare | strong | 2000-3500 | ④⑥⑪ |
| faq (long/short) | mid/weak | 800-1500／200-500 | 多数（[templates.md §3.4](templates.md)） |

### §7. LLMO 8原則＋書き手のクセ補正

1. 結論先出し（TLDR 必須） 2. H2 配下に箇条書き or 表を1つ以上 3. 数値の具体性 4. H1=1・H2=4-6 5. 専門用語は初出1行定義 6. 比較は3列以上の表 7. 出典明示 `<sup>[N]</sup>`＋References 8. 更新日表示

クセ補正: 箇条書き30%超NG／テーブル短3・長5個超NG／H2直後4文以内に本題／カッコ書き多用NG。引用は 2-4件（最大6）・1 H2 に2箇所まで・references-map.md 登録 ID のみ
