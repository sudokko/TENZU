すべての記事タイプ共通。一部セクションはタイプ別に省略可（§3.4）。

| # | セクション | 役割 | スロット名 | タイプ別省略 |

| 8 | 本文 H2 #4（注意点・FAQ） | 失敗パターン・年齢別注意 | 自由 | pillar/symptom 必須 |

| 10 | 末尾レコメンド3点 | 兄弟記事3本（urls.md §6 内部リンクルール） | `<RelatedPosts />` | 必須 |
| 11 | 参考文献リスト | `references` フロントマターから自動展開 | `<References />` | 引用がある記事のみ |

### 3.2 セクション別スロット仕様

#### `<Lead>`
- 120-180字。1問1答構造（「○○で悩んでいませんか？本記事では△△を解説します」）
- 絵文字は冒頭1個まで（pillar=0個・cluster=0-1個）

#### `<TLDR>`
- 箇条書き3-5行。各行は40字以内
- 末尾に1行「根拠: 本記事 §X / 引用[N]」を入れる（LLMO 7原則=出典明示）

#### `<InlineCTA>` （CTA形式①: 文脈テキストリンク）
- 本文中の自然な流れで1-2行のリンク
- フォーマット: 「→ [リンクテキスト]({url})」
- 文脈例: 「板書ずれは点描写 Lv.2 から段階的に改善できます。→ [Lv.選び方ガイドへ](/level-choice/)」
- weak タイプは本記事内にこれだけ。SKU カードは出さない

#### `<SkuCards />` （CTA形式②: SKUカード）
- `target_skus` フロントマターから自動展開（§3.3 ロジック）
- 1-3枚カード並列。それぞれ「Lv.バッジ／タスク名／問題数／¥価格／購入ボタン」
- target_skus 空配列の場合は **このコンポーネント自体をレンダリングしない**（CMS層で空配列ガード・FAQ short 等）

#### `<RelatedPosts />` （CTA形式③: 末尾レコメンド3点）
- 必ず3本。urls.md §6 の内部リンクルールに従い「兄弟Cluster→Pillar→商品ファミリー」の3軸で1本ずつ
- 手動指定（フロントマター `related: [slug1, slug2, slug3]`）も可だが、未指定時は自動アルゴリズム（同 parent_category → 同 parent_pillar → product-family）

### 3.3 `target_skus` からのCTA自動展開ロジック

```typescript
// 疑似コード（2026-05-28 統合反映：3 フェーズ・phase-1 は SKU 非公開）
function renderSkuCards(frontmatter) {
  const { target_skus, phase, cta_mode } = frontmatter;

  // ガード1: 空配列なら何も出さない
  if (!target_skus || target_skus.length === 0) return null;

  // ガード2: phase-0 は完全廃止（旧 deprecated・統合で完全削除）
  if (phase === 'phase-0') return null;

  // ガード3: 新 phase-1 = 仕込み（SKU 非公開）。SKU カードは表示しない。
  // 代替CTA: Web ジェネレータ / サンプルPDF / メール・LINE 登録
  if (phase === 'phase-1') return null;

  // phase-2 / phase-3 は target_skus 指定通りに展開（フィルタ無し・全140 SKU 販売前提）
  // 上限3枚
  return <SkuCards skus={target_skus.slice(0, 3)} mode={cta_mode} />;
}
```

## §4. 記事タイプ別CTA強度マップ（HO-B2-6）

### 4.1 強度3段階の定義

| 強度 | 配置 | 心理 | 使用CTA形式 |
|---|---|---|---|
| **weak** | InlineCTA（§3.2形式①）のみ | 情報提供主体・売り込み感ゼロ | 形式① |
| **mid** | InlineCTA + SkuCards 1-2枚 + RelatedPosts | 中立的に選択肢提示 | 形式①②③ |

**Tier 1: 教育系メディア**（例：kodomo-manabi-labo.net、すたペンドリル運営記事、ピノトレ運営記事）

- 採用条件：①運営者・編集体制が明示されている ②実績年数3年以上 ③一次情報性（独自取材・独自調査・現場経験）がある
- 引用方法：本文中で「教育情報メディア『◯◯』によると」と運営者名を明示／文末リンクではなく該当箇所からの直接リンク／引用ブロック使用可
- 役割：論文の硬さを和らげる「実践証言」「年齢別の手触り」
- 登録：references-map.md §11「教育系メディア・実践情報源マップ」に事前登録したものから使用

**Tier 2: 個人の受験ブログ・教育ブログ**

- 採用条件：①実名または安定したペンネームで継続運営 ②検証可能な実体験ベース ③医療・発達断定をしていない
- 引用方法：「中学受験親のブログ『◯◯』では〜という体験が語られている」のように主観であることを明示／断定ソースとして使わない
- 役割：「家庭でこう感じた」の温度の借用に限定
- 任意採用（必須ではない）

**NG**：①匿名まとめサイト ②運営者不明の教材販売サイト ③医療・発達特性を断定するブログ ④広告主体のキュレーションメディア

**競合性の扱い**：同一 KW で SERP 競合する相手でも、引用価値があれば明示リンクで敬意を払う。引用元を隠す・言い換えで誤魔化す行為は禁止（「敵を引用する」のは強者の作法・E-E-A-T 的にもプラス）。

**カウント**：§7.5 の「引用 2-4件・最大6件」「1 H2 最大2箇所」に Tier 1/2 を含めてカウント。論文を削って Tier 1 を増やすのではなく、温めたい H2 に1箇所追加する運用が基本。

### 7.6 書き手のクセ補正（research.md §1.8 補足2 と連動・2026-05-09 追加）

書き手本人が自覚している逸脱パターン。閾値は**目安**であり、記事の長さ・タイプによって運用調整する。

| 観点 | チェック内容 | 警告目安（記事の長さで調整） |
|---|---|---|
| 箇条書き比率 | 本文中の `- ` 行数 / 総行数 | 30%超で要見直し（散文化検討） |
| テーブル数 | 1記事のテーブル数 | 短記事3個超／長記事5個超で要見直し |
| 冒頭着地 | H1/H2 直後から本題（結論・問い・キメ）まで | 4文超かかったら要見直し |
| カッコ書き回数 | 本文中の `（〜）` の使用回数 | 多用していると感じたら本文展開 or 削除 |
