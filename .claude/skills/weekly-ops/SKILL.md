# /weekly-ops — 週次コックピット（B1 運転席）

## SSOT（必ず参照・複製しない）

- ブロック制・チャネル優先順位・縮退設計: [launch/operations.md §4-§7](../../../launch/operations.md)
- 北極星指標・UTM 規則: [engineering/analytics.md](../../../engineering/analytics.md)
- 月次判断基準（右肩上がりルール）: [launch/measurement.md §5](../../../launch/measurement.md)
- NG 語彙・SEO 例外・acquisition 運用 NG: [foundation/voice-tone.md §1・§7](../../../foundation/voice-tone.md)
- X 運用（週7＝専門家ポジ3＋店主メモ4・店主メモの人格設計と線引き・リンクはリプ欄）: [acquisition/sns-accounts.md §4.3](../../../acquisition/sns-accounts.md)・[channels.md §2.4](../../../acquisition/channels.md)・[sns-operations.md](../../../acquisition/sns-operations.md)

- 運転ログ: [launch/ops-log.md](../../../launch/ops-log.md)（追記専用・このスキルが書く）

## 手順

### 0. 状況把握

1. `launch/ops-log.md` の最新行を読む（前回の週・テーマ・持ち越しメモ）
2. 現フェーズを判定（operations.md §2 の基準線とログから推定し、冒頭で「今週は Phase X・第 N 週の想定で進めるわよ」と宣言。違えばオーナーが訂正する）
3. オーナーが「今週は縮退1/2」と言ったら §7 縮退表に従いプランを縮小（縮退2 なら X 草稿もスキップ）

### 1. 数値チェック（北極星3つだけ）

- **GA4 未開通**（`NEXT_PUBLIC_GTM_ID` 未設定 or オーナーが「まだ」）→ スキップし「数値なしモード」と明示。代わりに定性 1 問だけ聞く（「今週、外から反応あった？」）
- **開通後**: 次の記入テンプレを出してオーナーに貼ってもらう →

  ```
  ①流入元別 generated_pdf（GA4 探索 or イベント×utm_source）: 
  ②purchase 件数（paper / maker 別）: 
  ③Search Console クリック数（過去7日）: 
  ```

- 貼られたら ops-log の前週値と比較し、所見を **3 行以内**で返す。判断は measurement §5.1 準拠（前週比右肩上がりか。下降 2 週連続なら翌週 B1 で原因分析を予約）
- 虚栄指標（フォロワー・いいね・インプ単独）は聞かれても「見ない設計」と返す

### 2. NG ワード点検

1. voice-tone.md **§1「NG 語彙の grep 対象」**の語彙リストを読み取る（ハードコードしない・§1 が SSOT）
2. 直近 7 日に変更された公開系テキストを対象に Grep:
   - `web/content/articles/` `web/app/`（.mdx/.tsx）・`docs/drafts/`（.md/.mdx）
   - 対象抽出: `git log --since=7.days --name-only --pretty=format:` ＋ `git status --porcelain`（未コミット分・このリポジトリは未コミット作業が常態）の両方をフィルタ
3. ヒットは **ファイル:行＋前後文脈**で報告。SEO 例外（記事冒頭のクエリ引用・鉤括弧＋即転換の 2 要素・voice-tone §1）に該当するかを判定して「要修正／例外適合」に振り分ける
4. 「アプリ」表記（メーカーをネイティブアプリと誤解させる文脈のみ・voice-tone §7.1）も同時に見る

### 3. 今週テーマ決定（B2・B3 のプラン）

- **B2（記事）**: clusters.md の確定記事リストと `docs/drafts/articles/`・`web/content/articles/` の実在ファイルを突合し、①書きかけ最優先 ②未着手はフェーズ計画（[launch/phases.md](../../../launch/phases.md) の Phase 別公開物）順で 1 本提案。隔週ペースなので「今週は執筆週か・構成週か」も判定
- **B3（量産バッチ）**: フェーズ別の定型を提示 — Pinterest 週分 4-8 ピン（`/atelier/pins`）／DM 5 件（Phase 1-2 のみ）／IG カルーセル（完成記事があれば分解 1 本）。月初の週は月1タスク（広告メンテ・リール・note・measurement §5.1 月次チェック）を B3 に載せる
- 提案は**押し付けない**: 「今週の推奨」1 案＋「軽い代替」1 案の 2 択で出す

### 4. X 週 7 本の草稿（専門家ポジ 3＋店主メモ 〜4）

構成は [sns-accounts.md §4.3](../../../acquisition/sns-accounts.md) に従う。**専門家ポジ 3 本（三人称）＋店主メモ 〜4 本（一人称）**。縮退時は店主メモから削り、専門家ポジ 3 本を下限とする。

**A. 専門家ポジ 3 本（三人称・事実ベース・断定しない）** — 素材:

1. **論文・知見系**: evidence.md から。クッション表現（「〜という報告があります」）。同じ論文の使い回しは ops-log の過去テーマと重複しないよう散らす
2. **制作裏側・設計思想**: 直近の git log・decisions.md の新しい判断から「なぜこう作ったか」を三人称・専門店視点で
3. **記事・Tips 切り出し**: 公開記事の要点 1 つを 1 ポストに

**B. 店主メモ 〜4 本（一人称・書式「店主メモ｜」）** — [sns-accounts.md §4.3](../../../acquisition/sns-accounts.md) の人格設計と線引きに従う:

- 素材は 2 系統: ①制作判断・読んだ本や記事の感想（囲碁など思考・幾何系）＝git log や日々の制作から拾える ②**教育・受験・学校をめぐる親としての思索**（中受・塾選び・PTA・習い事の迷い）
- ②は**オーナーの実体験・思索なので捏造しない**。手順の冒頭で 1 問だけ聞く: 「今週、店主メモに書けそうな"親として考えたこと"ある？（受験・塾・学校まわり／読んだ本／囲碁でも）」。素材が返ればそれを膨らませ、無ければ①の制作判断系で本数を埋める（note-devlog-craft の「起きていないことは書かない」と同型）
- **線引き**（sns-accounts §4.3・3 層）: ①**書いてよい**＝親としての体験・迷い（中受・塾選び・進路・宿題・PTA）②**守る**＝子どもは匿名かつ非特定（顔・実名・学校名・塾名・成績・受験校を出さない／本人が将来読んで嫌がる粒度も書かない）③**禁止**＝TENZU 商品の効果の自家証言（法務理由・緩和されない）
- 専門家ポジと声を混ぜない（店主メモは一人称・冒頭「店主メモ｜」で始める）

**書式ルール**（1 本ごと・種別ラベルを付ける）:

```
── N本目｜専門家ポジ / 店主メモ（想定: 月〜日どこでも）───
本文（140字目安・リンクを含めない・ハッシュタグ0-2個）
※店主メモは冒頭「店主メモ｜」＋一人称

▼リプ欄（あれば）:
URL＋一言（UTM: utm_source=x&utm_medium=post&utm_campaign=<現行>&utm_content=<識別子>）
```

- **リンクは本文に入れない**（インプ 30-60% 減の抑制・channels §2.4）。URL は必ずリプ欄ブロックへ
- voice-tone §1 全面適用（専門家ポジも店主メモも）: 煽りなし（「今すぐ」「差がつく」「入学までに」NG）・診断語彙 NG・点つなぎを下に見ない・「アプリ」と書かない・効果断定 NG
- 表記: 初出は「点図形（点描写）」並記、以降は文脈で可
- 出力先: `docs/drafts/sns/x/<YYYY-MM-DD>.md`（当日日付・1 ファイルに 7 本・各行に種別ラベル）
- 末尾に**人間ゲートの注意書き**を必ず入れる: 「投稿前に 1 本 30 秒のトーン最終チェック（AI 比率 90% の残り 10%）。**店主メモは特に線引き（子どもが特定される粒度になっていないか・効果の自家証言になっていないか）を確認**。Buffer 予約後、投稿 15-30 分の初動コメントだけ見る」

### 5. チェックリスト出力＋ログ追記

1. 今週のチェックリストを出す（オーナーはこれを見て動くだけ）:

   ```
   ## 今週の運転（第N週・Phase X・縮退Lv0）
   ### B1（このまま完了）
   - [x] 数値チェック → 所見: …
   - [x] NG grep → 0件 / 要修正n件
   - [ ] X 7本を Buffer 予約（草稿: docs/drafts/sns/x/….md・各30秒チェック）
   - [ ] コメント/DM 返信（100%人間）
   ### B2: <記事テーマ>（執筆週/構成週）
   ### B3: <バッチ内容>（月1タスク: あり/なし）
   ```

2. `launch/ops-log.md` の表の**先頭**に 1 行追記（週開始日・縮退Lv・数値3つ（無ければ—）・B2/B3 テーマ・メモ/持ち越し）

## やらないこと

- 投稿・送信・予約の実行（**100% 人間**・voice-tone §7.3）。生成と点検まで
- 数値の捏造・推定値の記入（取れない値は「—」でログに残す）
- 縮退の押し付け（縮退はオーナーの宣言起点。ただし前回ログが縮退なら「今週は戻れそう？」と 1 回だけ聞く）
