# /dm-kit — ブロガー DM 支援キット

DM 運用（[channels.md §3](../../../acquisition/channels.md)・オーガニック 15%）の**人間がやらなくていい部分だけ**を持つ: リスト管理・下書き・期限管理。**選定の最終判断・思想チェック・具体言及の確定・送信・返信は 100% 人間**（[voice-tone §7](../../../foundation/voice-tone.md)・Meta 規制対応）。

## SSOT（必ず参照・複製しない）

- 選定基準・リスト作成・運用ルール・UGC 獲得: [acquisition/channels.md §3](../../../acquisition/channels.md)
- DM 3 通の構造（件名・段落・禁止事項・Stripe クーポン設定）: [acquisition/channels.md §4](../../../acquisition/channels.md)
- 反応者管理の列定義・2 週間判定・社交辞令の扱い: [launch/phases.md §7](../../../launch/phases.md)
- 運用 NG（AI 自動 DM・自動応答の禁止）: [foundation/voice-tone.md §7.3-7.4](../../../foundation/voice-tone.md)

## 大原則（破らない・頼まれても断る）

1. **送信・返信は 100% 人間**。このスキルは下書きとリスト更新まで
2. **スクレイピングによる大量抽出 → 自動 DM はしない**（候補は 1 件ずつ人間の目を通す前提）
3. **週 5 件ペース厳守**。週 5 件を超える下書きの量産を頼まれたら、設計（channels §3.3）を示して断る
4. フォローアップは**無反応 1 週間後に 1 回だけ**。社交辞令🟡は追撃しない
5. ステマ規制: 紹介は任意・提供品である旨の明示依頼を必ず文面に含める

## リスト: `docs/outreach/dm-list.csv`

列（channels §3.2 ＋ phases §7.1 を統合・このファイルが運用データの置き場）:

| 列 | 中身 |
|---|---|
| `id` | 連番（`b001`〜） |
| `added` / `sent` / `deadline` | 追加日／1 通目配信日／判定期限（=配信+14日・スキルが自動計算） |
| `name` / `url` / `platform` | 相手名・ブログ/アカウント URL・X/Instagram/note/Ameba/blog |
| `da` | ドメインパワー目安（DA 10-40 の中規模が最反応・channels §3.1） |
| `contact` | 連絡手段（フォーム > IG DM > X DM の優先順） |
| `article` | 言及対象にする相手記事の URL |
| `mind_check` | **思想チェック（人間専用列）**: `ok` / `ng` / 空欄。`ok` になるまで下書きに進まない |
| `status` | `候補` `1通目済` `実反応🟢` `社交辞令🟡` `無反応⚪` `フォロー済` `2通目済` `3通目済` `停止` |
| `evidence` | 反応根拠（紹介 URL・DM 引用） |
| `sent2` / `sent3` / `coupon` / `coupon_used` | 2 通目/3 通目送付日・クーポンコード・使用数 |
| `note` | メモ（スコアリング観点・紹介実績など） |

## 手順

### A. 候補の追加

1. オーナーから URL を受け取る（候補出しを頼まれたら WebSearch で「点描写/点つなぎ/知育プリント + ブログ」系の**個人ブログ**を探して提示してよい。法人メディアは除外）
2. **足切り 4 条件**を記事を読んで確認: ①ジャンル=知育・幼児教育・中受準備 ②直近 3 ヶ月更新 ③点描写 or 類似ワードの記事あり ④連絡手段あり — 1 つでも欠けたら理由を添えて不採用提案
3. スコアリング観点（DA・記事の質・拡散力・紹介慣れ）を `note` にメモして CSV に追記。`mind_check` は**空欄のまま**（人間が目視して `ok` を入れる）

### B. DM 1 通目の下書き

1. 対象行の `mind_check=ok` を確認（空欄/ng なら進まない）
2. `article` の記事を読む（WebFetch か本文貼り付け）
3. channels §4.1 の構造で下書き（件名＋4 段落・**約 450 字**・記事まとめ＋おためし点描写メーカー併記）
4. **2 段落目（相手記事への具体言及）は完成形にしない**: 記事から言及候補を 2-3 個（引用箇所つき）提示し、`【ここは自分の言葉で確定】` プレースホルダを残す
5. 禁止の自己チェック: 「アプリ」表記・βテスト感（「開業前」「最初の公開物」）・voice-tone §1 NG 語彙を grep して報告
6. `docs/outreach/dm/<id>-<相手名>.md` に保存（件名・本文・送信チャネル・チェック結果）
7. オーナーが確定・送信したら `sent`・`deadline`（+14 日）・`status=1通目済` を更新

### C. 反応判定の更新（週次・/weekly-ops B1 と併走可）

1. `deadline` 超過かつ `status=1通目済` の行を一覧化してオーナーに反応有無を聞く
2. 判定（channels §4.2 の実反応基準 a-d）: 実反応🟢／社交辞令🟡／無反応⚪
3. 🟢 → **2 通目（お礼）を即下書き**（24-48h 以内送信推奨・モニター予告＋UGC 意向確認・クーポン言及禁止）／🟡 → 何もしない（LP の発信者向け窓口待ち）／⚪ → 未フォローなら 1 回だけフォローアップ下書き、フォロー済なら `停止`

### D. 3 通目（Phase 3 到達時のみ）

- `status` が 🟢 系の行へ、本リリース＋クーポンの下書き（channels §4.3 の 5 段落・ステマ明示依頼込み）と **Stripe Promotion Code 設定表**（`[識別子]-FREE`・100% OFF 1 SKU・上限 30 回・60 日・単品のみ）を添えて出力

## 報告フォーマット（毎回）

- 更新した行（id・status の変化）／保存した下書きパス／**判定期限が 3 日以内の行**の警告／今週の残り送信枠（5 − 今週 `sent` 済み件数）

## やらないこと

- 送信・返信・フォローの実行／リストの一括自動収集／週 5 件超の下書き／`mind_check` の代行（人間専用列）／クーポンの 1・2 通目への混入
