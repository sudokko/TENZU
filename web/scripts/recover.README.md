# 手動リカバリ運用手順（メール不達の救済）

「課金したのにメール（DLリンク / ログインリンク）が届かない」客への手動対応プレイブック。
ツール本体＝[`recover.mjs`](./recover.mjs)（オーナー専用・ローカル実行のみ・ネットに出さない）。

- **メーカー（サブスク）= OTP ログイン**。不達時の救済＝**ログインリンクを発行して手渡し**
- **商品（単発 ¥200）= マジックリンク**。不達時の救済＝**サンクス（DL）ページのリンクを再発行**

どちらも発行関数は本番コードと同一（`auth.ts` / `checkout/success`）。ツールは Stripe 照合＋発行のガワ。

---

## まず大前提（これを怠ると手動対応が毎日の作業になる）

1. **到達性の地固めを先に**：SES の SPF / DKIM / **DMARC** ＋ **カスタム MAIL FROM**（From とのアライメント一致）。
   docomo 2025/2 以降のフィルタ厳格化対策。これで不達を 1〜2% に抑え、手動はあくまで残り物の網にする。
2. **初回アクセスはメールに依存させない**：
   - 商品＝Checkout 完了 → サンクスページがそのまま DL ページ（メールは後日再DL用の控え）。
   - メーカー＝Checkout 復帰 `/api/auth/verify?session_id=...` で即ログイン（メールは別端末・後日用）。
   → 手動リカバリが扱うのは「後日の再アクセスで不達」だけ＝非緊急・低頻度。

---

## 使い方

`web/` ディレクトリから:

```bash
node scripts/recover.mjs <メール または Stripe ID> [--resend] [--base=URL]
# or
npm run recover -- <メール または Stripe ID> [--resend]
```

| 入力 | 動作 |
|---|---|
| `okayama@example.com` | メールで横断検索（サブスク＋直近の商品購入の両方） |
| `cs_...` | Checkout セッション直指定（ダッシュボードからコピペが最速） |
| `cus_...` / `sub_...` | 顧客 / サブスク直指定（メーカー） |
| `pi_...` | PaymentIntent 直指定（商品） |
| `--resend` | **登録メール宛**に再送（スパム振り分け・一時不達用） |
| `--base=https://tenzu.jp` | 発行リンクのドメイン上書き（既定 `SITE_URL` → 無ければ tenzu.jp） |

出力＝入金/契約状況・金額・購入日・カード末尾4桁（本人確認用）・**コピペ用の再発行リンク**・**返信テンプレ3種**。

---

## 対応フロー（3ステップ）

1. **Stripe で入金/契約を確認**（ツールが代行）。払ってない宛先には発行されない。
2. **原因を切り分け**：
   - **スパム/一時不達**（多数）→ `--resend` で同じアドレスに再送＋「迷惑メール確認して」テンプレ①。
   - **ハード不達**（キャリアブロック等）→ 同じアドレスは無駄。別アドレスを聞く（下記 3 の本人確認つき）。
   - 切り分けは **SES のバウンス通知**（SNS / SES コンソール）を見れば一発。ハードバウンス＝別アドレス案件。
3. **本人へ手渡し**：
   - **既定は登録メール宛**（テンプレ②）。
   - **別アドレス希望時のみ**、テンプレ③で **購入日・金額・カード末尾4桁** を質問 → ツール表示と照合 → OK なら別アドレスへ。

---

## セキュリティ（厳守）

- 発行リンクは **有料アクセスのベアラ**。SNS・公開チャネルに貼らない。短命（メーカー＝30分）・原則一度きり。
- **別アドレスへ送る前に必ず本人確認**。ここが唯一の乗っ取り経路（攻撃者が「自分のアドレスに送って」と来る）。
- メーカーのログインリンクは verify 側で Stripe を再照合するため、**解約済みには無効**（安全側）。
- 発行は `scripts/recover-audit.log.jsonl` に追記（誰に・いつ・何を）。ミス/不正の検知用。
- ツールは **ローカルのみ**。`AUTH_SECRET` を含む `.env.local` を読むので、共有端末では実行しない。

---

## 必要 env（`web/.env.local`）

`STRIPE_SECRET_KEY`（必須）/ `AUTH_SECRET`（メーカーのリンク発行に必須）/ `STRIPE_PRICE_ENTRY` / `STRIPE_PRICE_FULL`（tier 表示）/ `SITE_URL`（リンクのドメイン）/ `SES_FROM_EMAIL` ほか（`--resend` 時）。
