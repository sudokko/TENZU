01 / RECOMMENDATION

まず、何を変えるか

現行の下部カードは間違いではありません。ただ、スマホではブラウザの下部UIや固定操作バーと重なりやすく、TENZUの主訴求を見せるには弱い。用途別に3つへ分けます。

採用

中央寄せフローティング

初回案内・レベル選び向け。画面上端から約42%、幅は左右15px余白、背景オーバーレイなし。画像は102×124pxを基準にします。

用途限定

下部カード

カートの事実通知に残します。親指で押しやすい一方、固定フッターと競合するため、safe areaと既存バーの高さを必ず加算します。

追加

文脈内カード

メーカーの使い方ヒントや記事内の関連案内向け。読み物・操作を覆わず、表示理由が最も伝わりやすい方式です。

03 / POSITION

「下部はダメ？ 中央がいい？」への回答

中央は目立ちますが、全面を塞ぐとGoogleが避けるよう求める侵入的インタースティシャルに近づきます。TENZUでは「位置は中央・振る舞いはバナー」が落としどころです。

中央寄せ・非モーダル

主推奨

  • ＋ 視線に入りやすい
  • ＋ 下部UIと競合しない
  • − 本文を一部覆うため小型化が必須

下部固定

通知向け

  • ＋ 親指で操作しやすい
  • ＋ カート通知と相性がよい
  • − ブラウザUI・固定バーと競合

文脈内

補助推奨

  • ＋ 邪魔になりにくい
  • ＋ 表示理由が伝わる
  • − 即時の視認性は中央より弱い

05 / FEATURES TO ADD

足した方がよい機能

現行管理画面は文言・画像・ページ・トリガー・統計まで揃っています。次に効くのはキャンペーン数ではなく、スマホでの見え方と表示理由を制御する機能です。

P0

端末別レイアウト設定

スマホは「中央寄せ / 下部 / 文脈内」、PCは「右下 / 文脈内」を選択。画像の有無・比率も端末別にします。

効果 大実装 中今回の核
P0

管理画面の実寸プレビュー

390px / 375px / PCを切り替え、本文の折返し・safe area・既存固定バーとの衝突を保存前に確認します。

事故防止実装 小〜中
P0

見出しフィールド

現行は本文だけ。画像・本文・リンクを流し読みされないよう、14〜18字の見出しを追加します。本文との役割を分けます。

視認性実装 小
P0

行動トリガーの組合せ

「秒数だけ」でなく、スクロール率・商品閲覧数・カート保有・ページ移動をAND/ORで組めるようにします。

誤爆削減実装 中
P1

開始・終了日時の予約

春キャンペーンを手動でON/OFFせず、JSTで開始・終了。終了後は自動停止し、過去設定は残します。

運用省力実装 小
P1

頻度を結果別に制御

クリック済みは終了、×で閉じたら30日休止、表示だけなら7日後にあと1回など、閲覧・閉じる・クリックを分けます。

機会損失削減実装 中
P1

下流成果までの統計

表示・クリック・閉じるだけでなく、ガイド完了・サンプル閲覧・PDF生成・購入まで管理画面で接続します。

意思決定実装 中
P1

保存前の自動検査

文字数、リンク切れ、alt、タップ領域、画面占有率、同時配信の競合、NG語彙をまとめて警告します。

品質保証実装 小〜中
P2

小さな比較テスト

本格A/B基盤ではなく、中央寄せと下部を2週間ずつ比較する期間テスト。購入など下流成果で判断します。

×だけでなく「あとで見る」を用意し、閉じると拒否を分けます。再表示はユーザーが選んだ時だけにします。

06 / IMPLEMENTATION GUARDRAILS

実装時に守る条件

中央寄せへ変える場合は、位置だけ変えて終わりにせず、カードの占有率・閉じ方・フォーカス・計測をセットで直します。

  • 背景オーバーレイ・スクロールロック・自動フォーカス移動は使わない
  • スマホ幅は左右15〜16px余白、カード高は原則ビューポートの30%以下
  • 閉じるボタンとCTAのタップ領域は44×44pxを目標（WCAG AA最低24pxを上回る）
  • カード外タップ、Esc、×の3経路で閉じられる
  • 表示アニメーションは200〜280ms、reduced motionでは無効
  • safe-area-inset-bottomと既存固定バーの高さを合算する
  • 表示計測は実際に1秒以上見えた時点、プレビューは除外
  • 同時1件、決済・管理・工房編集画面では抑制を維持

既存Campaign型への最小追加案

headline?: string
layout?: {
  mobile: "floating" | "bottom" | "inline"
  desktop: "corner" | "inline"
  imageVariant: "side" | "none"
}
conditions?: {
  minVisibleSec?: number
  minScrollPct?: number
  minProductViews?: number
  schedule?: { startAt: string; endAt: string }
}
frequency?: {
  onView: "lifetime" | "7d"
  onDismiss: "lifetime" | "30d"
  maxImpressions: 1 | 2
}
07 / RESEARCH SOURCES

今回読み込んだ根拠

特定ツールの売り文句ではなく、検索・アクセシビリティの公式資料と大規模ECユーザビリティ調査を優先しました。

  • Google Search Central — Avoid intrusive interstitials and dialogs全面を塞ぐ表示を避け、小さなバナーを使う判断の根拠。
  • Baymard Institute — Promotional Overlays on Page Load到着直後の宣伝オーバーレイが反射的に閉じられやすいという調査。
  • Baymard Institute — Avoid These E-Commerce Graphicsユーザー行動に応じたヘルプと、ページロード時の宣伝表示を分ける根拠。
  • W3C WAI — Target Size (Minimum)タップ対象24px以上、実装目標44pxの根拠。
  • W3C WAI — Focus Not Obscured固定パネルが背後の操作対象を完全に隠さないための根拠。
  • MDN — Popover API非モーダル表示・light dismiss・単一表示の実装方針。
  • web.dev — Popover and dialog中央配置でも非モーダルとして実装できる技術的根拠。
  • W3C WAI — Animation from Interactions不要な移動を抑え、prefers-reduced-motionを尊重する根拠。
