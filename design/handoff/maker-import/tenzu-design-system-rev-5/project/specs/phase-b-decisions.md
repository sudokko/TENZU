## Q3. モバイル点格子のピッチ

### 結論: **28px（mobile ≤ 600px）／ 24px（tablet・desktop）**

| 環境 | viewport | pitch | dot opacity | dot radius |
|---|---|---|---|---|
| **Mobile** | ≤ 600px | **28px** | 0.16 | 1px |
| **Tablet** | 601 – 1023px | 24px | 0.16 | 1px |
| **Desktop** | ≥ 1024px | 24px | 0.16 | 1px |

### 根拠

| # | 観点 | 24px のまま | 28px へ広げる |
|---|---|---|---|
| **A. iPhone 標準 (375px)** | 横 15.6 列 — 視覚的に密 | 横 13.4 列 — 適切な密度 |
| **B. ピッチ／余白比** | margin 24 = 1 ピッチ | margin 24 ≠ 整数比だが視覚的に「呼吸」が出る |
| **C. UI 要素との干渉** | 16-24px の文字や icon と干渉しやすい | 28px > 文字高 24px、ドットが「下地」に退く |
| **D. 印刷 5mm 方眼との関係** | 1x DPR で 24px ≒ 6.3mm（5mm より太い） | 28px ≒ 7.4mm — 教科書方眼に近い |
| **E. iPad / desktop との整合** | 全環境同一 | 環境差が出るが、24/28 は 7:6 で離散 |

**結論の決め手**: B+C — モバイルは文字密度が物理的に高くなるため、点格子は一段「退く」べき。デスクトップは情報量が多いため 24px の規則感を維持。

### 実装

```css
:root {
  --dot-grid-pitch: 24px;          /* default = tablet+desktop */
}
@media (max-width: 600px) {
  :root {
    --dot-grid-pitch: 28px;
  }
}
```

背景画像は `radial-gradient(circle, var(--dot-grid-color, #1A1F2A) var(--dot-grid-radius, 1px), transparent var(--dot-grid-radius, 1px))` を `background-size: var(--dot-grid-pitch) var(--dot-grid-pitch)` で繰り返す。`background-position: 0 0` 固定。

### 例外パターン（点格子を載せない場所）

| 場所 | 理由 |
|---|---|
| **CTA 最強ボタン**（accent ベタ塗り） | 注目集中の妨げ |
| **Hero に load される写真／グラフィック領域** | 視覚的混雑 |
| **モーダル・dialog 内部** | コンテンツ集中 |
| **PDF 印刷の作業面**（子の鉛筆が走るエリア） | 商品の点と衝突（Q5 で詳述） |
| **画像・SVG 図形の上** | 線質との干渉 |
| **`.parents-warm` カード内** | 寄り添う温度を出すため余白に集中 |

## Q5. 印刷 PDF substrate に薄い点格子を載せるか

### 結論: **作業面（worksheet area）は載せない／パッケージ面（表紙・親向け解説・改訂履歴）は載せる**

PDF を 3 つのレイヤーに分けて判定する：

| PDF 内のレイヤー | 役割 | 点格子 | 理由 |
|---|---|---|---|
| **L1. 作業面**（worksheet — 子が鉛筆で写すページ） | 子の作業域 | ❌ **載せない** | 商品の「点」（点描写の起点）と背景の「点」が衝突する。これは TENZU の核を壊す致命的干渉 |
| **L2. パッケージ面**（表紙・タスク説明・親向け声かけ・改訂履歴） | 親が読むメタ情報 | ✅ **載せる** | サイト体験との同一性（visual-identity §1.2）／「これは TENZU の紙です」と分かる |
| **L3. サンプル領域**（フッターの記入見本など） | 記入例 | ❌ **載せない** | L1 と同じ理由 |

### L1 作業面の物理ルール

- 用紙: A4 縦・横の選択は商品ごと
- substrate: 完全な白 `#FFFFFF`
- 点描写の点（puzzle dots）: `#1A1F2A` ベタ・半径 0.8mm 程度（実物検証で調整）
- 点描写の点間隔: SKU 毎に 5mm / 7mm / 10mm 等（pack-design.md に依存）
- ガイド枠線: なし。または `line-thin #D8D6CF` 0.5pt 細枠
- ヘッダ／フッタ余白: 12mm 以上

### L2 パッケージ面の物理ルール

- substrate: `#FFFFFF` + **印刷点格子 5mm ピッチ、`#1A1F2A` 12% opacity、点半径 0.2mm**
  - サイト 28px = 7.4mm との対応で、印刷時は 5mm に縮めて「紙の感触」を出す
  - opacity は画面 16% → 印刷 12% にやや下げる（インクの再現で濃く乗るため）
- 表紙下半分・親向けブロック内のみ。**全面ベタ載せはしない**（visual-identity §3.2 密度設計：for-parents は余白最大）

## Q3 + Q5 の統合: 「点」が持つ意味の整理

TENZU には 3 種の「点」が登場し、混線を防ぐためレイヤー分けする：

| 点の種類 | 用途 | 物理仕様 | 場所 |
|---|---|---|---|
| **ブランド点格子**（system 背景） | 「TENZU の紙の上にいる」感の演出 | 24/28px ピッチ、opacity 0.16、`#1A1F2A` | Web 全面・PDF パッケージ面 |
| **商品点**（点描写の puzzle dots） | 子の作業対象 | 5/7/10mm 等、ベタ `#1A1F2A` | PDF 作業面のみ |
| **記入点**（子が打つ点） | 子の出力 | 鉛筆任せ | PDF 作業面の上（user input） |

**3 つの点が同一面に重ならない**設計が rev.5 の隠れた骨。
