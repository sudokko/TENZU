## Q1. SVG 線質の方針

### 結論: **ruled straight lines（直線維持） + 端点の round cap で温度を 1 段だけ持たせる**

ロゴは「ハイブリッド案 (b)」で骨格直線＋端点のみ素材感を出した。**SVG 図形（9 タスク・サンプル）も同じ思想で揃える**が、教材の機能性を最優先にして、揺らぎ・手描き線・波線は採用しない。

### 採用しない方向（rev.5 で却下済み）

- ❌ 波線・wobbly stroke（rev.4 直線を曲げる）
- ❌ stroke-dasharray でランダム揺らぎ
- ❌ Rough.js 系の手描き化
- ❌ 紙繊維ノイズ・ペーパーテクスチャ

### 採用するルール（locked）

| 項目 | 値 | 備考 |
|---|---|---|
| stroke 色 | `#1A1F2A`（fg） | accent teal は「正解線・補助軸」のみ |
| stroke 幅 | **1.5px** 基本 / 2px 強調 / 1px 補助 | 3 段階を厳守 |
| stroke-linecap | **`round`** | ロゴ Ξ-form E の端点処理と整合 |
| stroke-linejoin | **`round`** | 角を硬く見せない |
| dot（点描写の起点ドット） | 半径 2px 円・ベタ `#1A1F2A` | 図形 SVG 内で puzzle dots を再現するときの規格 |
| 補助線（点線） | stroke-dasharray: 3 3 / 4 4 | 軸・補助グリッド用 |
| accent teal の使い所 | 正解線・到達後の線・サンプル overlay | それ以外には使わない |
| viewBox | 一律 **`0 0 64 64`** | 9 タスク図形の card 内表示用 |
| 余白 | viewBox 内 8px 以上 | クリップ防止 |

### 物理 SVG テンプレ（9 タスク共通）

```html
<svg viewBox="0 0 64 64" xmlns="http://www.w3.org/2000/svg" role="img" aria-label="（タスク名）">
  <!-- background dot lattice (optional, opacity 0.16) -->
  <g class="lattice" opacity="0.16" fill="#1A1F2A">
    <!-- 5x5 dots at 12px pitch -->
    <circle cx="8"  cy="8"  r="1"/>
    <!-- ... -->
  </g>

  <!-- guide lines (dashed) -->
  <g class="guide" stroke="#1A1F2A" stroke-width="1" stroke-dasharray="3 3"
     stroke-linecap="round" fill="none" opacity="0.35">
    <!-- e.g. symmetry axis -->
  </g>

  <!-- primary figure -->
  <g class="figure" stroke="#1A1F2A" stroke-width="1.5"
     stroke-linecap="round" stroke-linejoin="round" fill="none">
    <!-- polylines drawn corner-to-corner across lattice points -->
  </g>

  <!-- answer / overlay (accent) — used in completed state only -->
  <g class="answer" stroke="#2C6E7F" stroke-width="1.5"
     stroke-linecap="round" stroke-linejoin="round" fill="none">
    <!-- ... -->
  </g>
</svg>
```

### 9 タスク図形の描き分けルール

| # | タスク | 主構成 | accent 使用 | 補助線 |
|---|---|---|---|---|
| 1 | **模写** (copy) | 左に手本図 + 右に空白格子 + 中央矢印 | 右図の完成例のみ accent | なし |
| 2 | **線対称** | 左半分の図 + 中央 vertical axis（dashed）+ 右半分の鏡像（accent） | あり（鏡像） | 中央軸 dashed |
| 3 | **回転** | 元図 + 弧の矢印 + 回転後（accent） | あり（回転後） | 回転中心の小十字 |
| 4 | **平行移動** | 元図 + 矢印 + 平行移動後（accent） | あり（移動後） | 移動量を示す軸 |
| 5 | **拡大縮小** | 小さい元図 + 中央矢印 + 大きい相似形（accent） | あり（相似形） | スケール比の補助線 |
| 6 | **かさね** (overlay) | 2 つの図形が部分的に重なる | 重なり部に teal fill 8% | なし |
| 7 | **分解** | 大きな図形 → 分割線 → 構成パーツ群 | 分解後パーツに accent | 分割線 dashed |
| 8 | **欠け補完** | 一部 dashed（欠けた辺）+ 補完で完成（accent） | あり（補完辺） | 欠け辺 dashed |
| 9 | **立体** | 2D 平面図 + 矢印 + 等角投影の 3D | 3D の見える辺に accent、隠れる辺は dashed | 立体の補助辺 |

### 「端点の温度」をどう物理的に出すか

- `stroke-linecap="round"` で線端を半円に
- 線の **両端が dot を「触れない」visible gap** を 0.5px 残す（ロゴ Symbol のコーナードット浮きと整合）
- これで「点と線がまだ繋がっていない」TENZU の物語が SVG 図形にも継承される

### 例外: ロゴ Symbol / Wordmark のみ素材感を強める

- ロゴ → 鉛筆筆致・端点に揺らぎ・3-5% feathering（[logo-regenerate-brief](../uploads/logo-regenerate-brief.md) 既定）
- SVG 図形 → 直線維持・素材感入れない（教材機能優先）
- **両者の温度差**は意図的：ブランドの「ストーリーを語る面（ロゴ）」と「機能を運ぶ面（タスク図）」の分業

## Q6. 「店主の痕跡」運用ルール

### 結論: **5 種の痕跡 × 場所別ルール表 × 1 ページ最大 2 個**

3 DR が共通して「全ページに店主の痕跡を散らす」と提言したが、無制限に散らすと「個人運営の手作り感」（visual-identity §V4 NG）に転落する。**5 種の痕跡を分類し、各場所での頻度・トーンを表で固定する**。

### 痕跡 5 種

| # | 種別 | 内容 | 文字数目安 | フォント | 配置 |
|---|---|---|---|---|---|
| **T1** | **観察メモ**（per-SKU） | 「ここを見てください」型・タスクの観察ポイント | 40-80 字 | Klee ① label + Pencil ② body | 商品ページ中段 |

### トーン規則

#### 必ず守る

- **「同じ親として先に気付いた」立場**（brand.md §9 P3）
- **一人称は「店主」または無記名**。「私たち」「弊社」「TENZU では」は使わない
- **日付・改訂は数値（Plex Mono ③）で固定**。「先日」「最近」は禁止
- **観察対象は figure / level / task。親の心配や子の出来不出来には触れない**

#### 禁則語彙（再掲・brand.md §11.2 と整合）

- ❌ 「〜してあげましょう」「〜が大切です」（指導語彙）
- ❌ 「処方箋」「特効薬」「弱点」「診断」（不安語彙）
- ❌ 「がんばろう」「やりきろう」「できた！」（達成煽り）
- ❌ 「点つなぎを卒業」（比較煽り）
- ❌ 「研究によると…」「専門家が…」（権威マウント）

#### 推奨語彙

- ◯ 「ここを見てください」「目を動かしてみてください」（観察への誘導）
- ◯ 「次は明日でも大丈夫です」（圧低減）
- ◯ 「TENZU では…という根拠で…を選んでいます」（クールな引用）
- ◯ 「お疲れさまでした」「今日の 1 枚」（落ち着いた声かけ）
- ◯ 「v1.3 — 線太さを 0.5pt 増しました」（事務的・正確）

### 更新頻度ルール

- **T1 観察メモ**: SKU 出荷時に必ず付ける。後で追記しない（観察は最初の判断）
- **T2 改訂履歴**: バージョン番号と紐づけ。改訂したときだけ追加
- **T3 選定理由**: SKU 出荷時または Lv 構成変更時のみ
- **T4 親へのひとこと**: SKU 出荷時に必ず付ける
- **T5 開発ノート**: 月 1 回程度の更新（読み物としての密度を保つ）
