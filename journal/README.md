# TENZU 開発記録ジャーナル

TENZU（点描写プリント専門店）の設計プロセスを、Claude Code との協業を中心に記録するアーカイブ。

## このジャーナルの位置づけ

- **目的**: 個人開発者として AI と協業しながら事業を設計するノウハウを、後で見返せる粒度で残す
- **使い道**:
  1. 自分用ナレッジベース（他プロジェクトに転用可能なコツの抽出）
  2. 他者に見せる可能性を残す（技術ブログ転載・採用面接資料等）
  3. TENZU プロジェクト自体の透明性記録
- **粒度**: 1 トピック = 1 エピソード記事（各 2,000〜3,000 字）
- **公開可否**: 各エピソードのフロントマター `public_safe` で判定

## 設計書（docs/）との棲み分け

| ファイル群 | 役割 |
|---|---|
| `docs/*.md`（pack-design.md 等） | **設計の最新仕様**（What） |
| `docs/journal/*`（このディレクトリ） | **設計に至る判断の記録**（Why / How） |
| `memory/session-archive.md` | Claude Code 継承用メモ（自分用・略記） |

journal は「人が読むためのアーカイブ」、memory は「Claude が次セッションで参照するための圧縮メモ」。

## エピソード記事のフォーマット

```markdown
---
ep: EP-XXX
title: タイトル
date: 2026-XX-XX            # 出来事の発生日
session: セッション識別      # 該当セッションの目印
themes: [tag1, tag2]         # テーマタグ
related_docs:                # 関連設計書
  - docs/pack-design.md
status: draft | published    # 執筆ステータス
public_safe: true | false    # 外部公開可否
---

# タイトル

## 何が起きたか（要約）
1 段落で結論ファースト。

## 状況・背景
判断に至るまでの文脈。

## やり取りの中身
具体的なプロンプト・AI 出力・対話の流れ。引用は実物に忠実に。

## なぜそう判断したか
Why の記録。後で見返した時の本体価値はここ。

## 学び（一般化できるノウハウ）
他プロジェクトに転用できる形で抽出。1〜3 個。

## 関連エピソード
- [EP-YYY](EP-YYY-slug.md) — 関連の理由
```

## 運用ルール

1. **書きすぎ注意**: 1 エピソード 3,000 字を上限目安に
2. **後日改定の追記**: 後で TENZU の方針が変わったエピソードは、末尾に「YYYY-MM-DD 追記: ここでの判断は EP-ZZZ で改定」と書き足す
3. **session-archive.md との二重管理を避ける**: archive は簡略要約、詳細は journal に書く
4. **文体**: 中立記述（チャット時のキャラクター語りはここには持ち込まない）
