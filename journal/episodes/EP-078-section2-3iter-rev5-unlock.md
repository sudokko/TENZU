# §2 再設計 3 段反復 → Design rev.5 着手判断（構造ではなく温度設計だった）

## 何が起きたか（要約）

LP §2 の再設計を 3 回反復したが、問題は §2 の構造ではなく rev.4 デザインシステム自体の温度設計だと判明し、rev.4 LOCKED の縛りを全解除して Design rev.5 着手に踏み切った。3 段反復は、① GPT-5 提案「課題から選ぶ × レベルから選ぶ二タブ ＋ 4 群カード」をオーナーが「分類した感が強い」と却下、② 第三専門家「キュレーション 3 本上層」を「ターゲット 8 セル分散（年齢 × 習熟度）で curation 不可」と却下、③ そこで初めて「§2 構造ではなくデザインシステム rev.4 の温度設計そのものが原因」と特定。rev.5 の構成要素を Code 側 PoC で先に検証し、3 階層フォント（Klee One 600 書写体 ／ Zen Kurenaido 鉛筆筆致 ／ Plex 構造）・真っ白 `#FFFFFF` + 点描写格子背景（24px ピッチ・dot opacity 0.16）・ボックス削減（dashed divider のみ）・1.5px solid teal の直線アンダーライン・メモ系の左マーカー（2px teal border）を Design rev.5 で正式化する方向で合意した。4 群グルーピング（見て写す／かたちを動かす／重ねる・分ける／立体でとらえる）は `pack-design.md §13.7` に SSOT 化し、「分類器 UI」ではなく**棚レイアウト＝情報アーキテクチャ**として温存した。

## 状況・背景

EP-077 でオーナーから「§2 の練り直しは正直イマイチ」判定が出たあと、類似商材 LP の DR を回す前段として、まずは §2 の構造案を 2-3 種類提示してみる方針で着手した。当初の見立ては「9×5 マトリックスでも 5 段階旅カードでも違和感が残るなら、見せ方の上位レイヤー（タブ切替・キュレーション）を変えれば解決する」という構造仮説だった。

この見立ては rev.4 のデザインシステムが「locked」だったことで強化されていた。配色・タイポ・ロゴ・余白スケールが固定されている前提で、構造（IA とコンポーネント）だけを動かして解にたどり着くという縛りの中で考えていた。結果として「構造のバリエーションを増やして当てに行く」モードに入っていた。

## やり取りの中身

第 1 反復は GPT-5 案「課題から選ぶ × レベルから選ぶ二タブ ＋ 4 群カード」。タスク軸を「課題（言語化された困りごと）」と「レベル（年齢・習熟度）」の 2 タブに分け、選んだタブ下に 4 群カード（見て写す／かたちを動かす／重ねる・分ける／立体でとらえる）を並べる構造。実装可能性も整っていたが、オーナー判定は「分類した感が強い」。タブ切替で次元削減しても、「分類して並べる」アプローチ自体が温度を冷やしていた。

第 2 反復は第三専門家への相談で出てきた「キュレーション 3 本上層」案。トップに「店主のおすすめ 3 本」「今月の定番 3 本」「初心者の最初の 3 本」のような curation を置き、その下に従来構造を畳む。これも実装可能性は十分だったが、TENZU のターゲットは年齢（年中〜小2）× 習熟度（公文家庭／知育意識／不安層）の組み合わせで 8 セル程度に分散しており、「全員に響く 3 本」が curation として成立しない。1 つの curation セットが特定セルだけに刺さると、他セルが疎外感を持つ構造になる。却下。

第 3 反復は「では §2 の構造ではないとしたら、何が問題か」という問い直しから始まった。仮説をひっくり返すと、rev.4 で確定した「クリーム紙 `#F4F2ED` ＋ 構造的 Plex タイポ ＋ ボックス多用」の組合せが、点描写プリント＝家庭向け学習教材という商材の温度感に対して構造寄りすぎる、という見方が浮かんだ。問題は §2 の見せ方（IA）ではなく、視覚言語そのものの温度設計だった。

ここで rev.4 LOCKED を一旦外し、Code 側で proof-of-concept を回した。`web/app/preview/page.tsx` に LP 全体を v5 適用 sample として作り直し、`web/app/wireframe/page.tsx` に §2 4 群ワイヤーを残した（タブ二択は不採用が確定したが構造検証物として保管）。`web/app/tokens.css` に Klee One ＋ Zen Kurenaido フォントトークンを追加した。

PoC で確定した v5 要素は 5 つ。① 3 階層フォント：Klee One 600 書写体 = 大見出し／Zen Kurenaido 鉛筆筆致 = 温度コピー／Plex = 構造・メタ・数字。② 真っ白 `#FFFFFF` + 点描写格子背景（24px ピッチ・dot opacity 0.16）：クリーム紙の温度を 1 段ニュートラルへ戻し、紙の温度は背景の点描写格子で出す。③ ボックス削減：dashed divider のみに集約。④ 1.5px solid teal の直線アンダーライン：§セクション H2 用、波線は不採用。⑤ メモ系の左マーカー：2px teal border。

並行で 4 群グルーピング（見て写す／かたちを動かす／重ねる・分ける／立体でとらえる）の位置付けを訂正。GPT-5 案では「分類器 UI」として §2 タブの中に組み込まれていたが、これを「分類器」ではなく**棚レイアウト＝情報アーキテクチャ**として `pack-design.md §13.7` に SSOT 化。商品ページや記事の見出し構造を支える IA として温存し、§2 のフロントエンド構造とは切り離した。

不採用案も明確にリスト化した。タブ二択／キュレーション上層 3 本／Hero CTA 3 本拡張／紙繊維ノイズ／紙クリーム色 `#F4F2ED`（rev.4 で採用したが rev.5 で撤回）／波線アンダーライン／こぐま会型順序カリキュラム／Z 会型学年タブ／Sensory タグ（#ヒラメキ）／「想像のトビラがひらく」系コピー。これらは再提案 NG リストとして `design/handoff/rev5-brief.md` に明記した。

## なぜそう判断したか

3 反復で構造のバリエーションを当てに行ったが解にたどり着かなかった時点で、「仮説の立てる場所が間違っている」可能性を真面目に検討すべきだった。仮説の立て直し（§2 の構造ではなく rev.4 そのもの）に踏み込んだのは、「微調整の積み重ねで本質解決に至らない」ことが 3 反復で確実に判定できたからだ。それ以上反復しても収束しない見込みが強かった。

rev.4 LOCKED を全解除した判断は重い。一度 locked した視覚言語を再 unlock するコストは、Design セッションのやり直し・LP 実装の手戻り・他成果物（商品ページ・記事・Maker App）の手戻り含めて大きい。それでも unlock を選んだのは、§2 の問題が「構造の問題か温度の問題か」の切り分けで温度側だと特定できたからで、温度の問題なら locked のまま小手先で当てに行くより、unlock して根本から作り直す方がトータルコストが小さいと判断した。

4 群グルーピングを「分類器 UI」から「棚レイアウト＝情報アーキテクチャ」へ位置付け直したのは、第 1 反復で却下されたのが「分類器として §2 タブに乗せた」見せ方であって、4 群そのものの中身は商材整理として有用だったからだ。中身を破棄するのではなく、適用先を変えて温存する。IA レイヤーに移すことで、商品ページ・記事の見出し設計に再利用できる。

PoC を Code 側で先に回した判断は、Design セッションを再起動する前に「v5 の方向が実装上成立するか」を見ておきたかったから。Klee One や Zen Kurenaido のような書写体・筆致系フォントは、ブラウザでの表示・配信性能・モバイルでの可読性に実装側のリスクがある。Code で先に proof-of-concept を作って成立を確認してから Design rev.5 の正式化に進む順序にした。

## 学び（一般化できるノウハウ）

1. **3 反復で解にたどり着かなければ「仮説の立てる場所」を疑う** — 構造のバリエーションを 3 種類試して全部却下されたなら、構造ではなく上位レイヤー（視覚言語・温度設計）に原因がある可能性が高い。それ以上構造で殴っても収束しない。

2. **「構造の問題か温度の問題か」の切り分けは 3 段反復で確実に判定できる** — 1-2 反復では構造の精度不足の可能性が残るが、3 反復で全部却下されたら温度側の問題と特定して良い。切り分けが付いたら locked を外す。

3. **locked は手戻りコストではなく根本コストで判断する** — 一度 locked した視覚言語の unlock は手戻りが大きい。だが locked のまま小手先で当てに行くより、unlock して根本から作り直す方がトータルコストが小さい場合がある。手戻りコストではなく「問題が温度なら温度から直す」根本コストで判断する。

4. **不採用案は「再提案 NG リスト」として明文化する** — 反復の中で却下した案を明文化しないと、別セッションで同じ案が再提案される。`rev5-brief.md` のような handoff ドキュメントに NG リストとして残すことで、Design セッションの収束時間を短縮できる。
