# SNS 素材をブラウザに触らせず作る（5 アカウント開設と Pinterest / IG 初回投稿）

## 何が起きたか（要約）

EP-129 で決めた 2 層の名義に沿って SNS 5 アカウントを開設し、Pinterest と Instagram の初回投稿を実行した。素材づくりで方針を変えたのが要点で、**ブラウザのスクリーンショットに頼らず、スクリプトで直接 PNG を書き出す**基盤を作った（`export-pins.ts` / `export-ig-carousel.ts`）。ブランド書体 Klee One を fontconfig 経由で読ませ、デザインシステムの見た目そのままで出力する。開店時のボードは 7 つの計画から 3 つへ絞った。

## 状況・背景

SNS 素材は「作れる」ことより「毎週作り続けられる」ことが問題だった。ブラウザで表示してスクリーンショットを撮る方式は、1 枚なら早いが、8 枚 × 毎週になると手作業のコストが積み上がる。しかも撮るたびに余白やスケールが微妙にずれる。

もう一つの制約は書体。ブランドの見た目は Klee One に依存しており、汎用のデザインツールでは同じ字面が出ない。

## やり取りの中身

**オフライン生成にした**。商品データから直接 SVG を組み、フォントを埋め込んで PNG へ焼く。ブラウザもヘッドレスも介さない。Klee One は fontconfig 経由で解決させることで、システムにインストールされた状態と同じ字面が出る。

**確定ハンドルは割れた**。設計では「名義内で 1 つ」に揃える方針だったが、媒体仕様と先行取得の結果、Pinterest は `tenzuinfo`、Instagram は `tenzu.jp`、X は `sudocraft_jp`、Ameba は `sudo-craft` になった。**実物を正とする**と決め、コード側の SSOT（`web/app/sns.ts`）と設計側の記録を実態へ合わせた。

**ボードを 7 → 3 へ絞った**。開店時点でピンの在庫がないボードを並べても、空の棚が並ぶだけで実在感が下がる。中身を出せる 3 つに集中した。

**P2「難度ちがい」の設計を直した**。同じ巻の中で難度を比べる作りになっていたが、**巻をまたいだラダー**として見せるほうが「体系がある店」という差別化に直結する。テンプレートの意味づけを修正した。

## なぜそう判断したか

**「毎週やる作業」を最初に自動化した**。SNS は開店後に継続する運用で、1 回のコストより 52 回ぶんのコストで考えるべき領域だった。スクリーンショット方式は初期コストが低いが、**再現性が無く、変更のたびに全部撮り直しになる**。データから生成する形にしておけば、商品が増えても文言が変わっても、走らせ直すだけで済む。

**ハンドルの不統一を受け入れた**。揃えるためにアカウントを取り直す選択もあったが、既に確保したハンドルを捨てるリスク（他者に取られる）のほうが、名義が少し割れる不都合より大きい。**設計と実物がずれたら、動かせないほうを正にする**。

**空のボードを作らなかった**。棚の数は実在感の指標だが、空の棚はむしろ逆に働く。数より中身を優先した。これは記事の段階公開（EP-133）と同じ判断構造である。

## 学び（一般化できるノウハウ）

1. **継続する作業は、初回のコストではなく年間のコストで方式を選ぶ** — スクリーンショットや手作業は初回が速い。しかし毎週繰り返すなら、データから生成する仕組みのほうが早く元が取れる。

2. **ブランド書体を使う出力は、レンダリング経路を自分で持つ** — 外部ツールに依存すると、字面が変わる・使えないという制約に縛られる。フォント解決まで含めて自前で持つと、見た目の一貫性を保証できる。

3. **設計と実物がずれたとき、動かせないほうを SSOT にする** — 先に取得したハンドルや、媒体の仕様は動かせない。設計書のほうを実態へ合わせ、ずれた理由を記録する。
