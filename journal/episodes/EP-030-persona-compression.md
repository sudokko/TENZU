# ペルソナ8人格→実質6層への圧縮——「全員に刺さる」より「使える設計図」を優先

## 何が起きたか（要約）

TENZU のターゲット保護者を「8人格構成」として詳細に定義した後、記事設計に使える粒度として「実質6層」に圧縮・整理した。8人格は「全員に刺さるコンテンツを作りたい」という欲から生まれたが、粒度が細かすぎると記事設計の分岐が増えて書けなくなる。「記事を書く時に参照できる設計図」として機能する最小の粒度に絞り込んだ。

## 状況・背景

2026-05-02 のセッション、B-2 コンテンツ設計（Phase 0-4）でペルソナを確定する作業を行った。ペルソナ設計の目的は「誰のためにどんな記事を書くか」を明確にすることだ。

最初に作った8人格は以下の構成だった：
- **P1（年齢層別×サブペルソナ2）**: 就学前（3〜5歳の親）× 受験志向/一般層 = 2人格
- **P2（年齢層別×サブペルソナ2）**: 小学校低学年（6〜9歳の親）× 受験志向/一般層 = 2人格
- **P3（年齢層別×サブペルソナ2）**: 小学校中学年（10〜12歳の親）× 受験志向/一般層 = 2人格
- **P4**: 発達・療育系（発達特性を持つ子の親）
- **P5**: 教員・支援者（プロフェッショナル利用）

計8人格。「点描写に関心を持つ保護者の全範囲をカバーしたい」という意図から生まれた設計だった。

## やり取りの中身

8人格を定義した後、「この8人格のために別々の記事を書く」設計を検討し始めたところで問題が見えてきた：

> 「8人格のうち、年齢層別×受験/一般のサブ分割は、記事設計のレベルでは分岐を使い分けられない。P1受験層向け記事とP1一般層向け記事を別に書くのは現実的じゃない。記事は基本的に『就学前の保護者』に向けて書いて、中で受験層への言及を混ぜる——という方が量産できる。」

8人格が「全員に別々に刺さる記事を作りたい」という欲から来ていたことが確認された。しかし記事設計の現実は「主な読者層を1〜2層想定して書く、他の層にも刺さるように配慮する」だ。

圧縮後の「実質6層」（`content-design-research.md`）：

| 層 | 特性 | 主要コンテンツ |
|---|---|---|
| **L1 就学前（受験志向）** | 3〜5歳・小学校受験を意識・高い教育投資意欲 | 難度・先取り・受験連動記事 |
| **L2 就学前（一般層）** | 3〜5歳・「楽しく伸ばしたい」・コスパ重視 | 入門・楽しさ訴求記事 |
| **L3 小学校低学年** | 6〜9歳・図形の苦手意識・算数補強として | 症状ベース・苦手解消記事 |
| **L4 小学校中学年** | 10〜12歳・入試対策・理科図表への応用 | 中受連動・本格訓練記事 |
| **L5 療育・発達支援** | 特性あり・感覚統合・書字困難 | 療育文脈・支援者向け記事 |
| **L6 教員・支援者** | プロ利用・授業・療育現場での活用 | 専門家向け・一括購入案内 |

L1/L2 は「就学前層」として同じ記事で扱い、受験色の強弱でトーンを変えるだけにした。L3/L4 は年齢が違えど「学習補強」という文脈が共通するため、記事内で両方を想定して書ける。

また「診断機能」（子どもの特性を入力して適切な商品を提案する機能）も合わせて検討したが、不採用とした：

> 「診断機能を実装するとメンテナンスコストが継続的にかかる。記事で『こんなお子さんに向いています』を丁寧に書けば、診断と同じ役割を果たせる。静的なコンテンツで診断機能を代替する方がスケーラブル。」

## なぜそう判断したか

「8人格→6層」への圧縮は、ペルソナの目的を「記事設計の道具」として再定義したことから来ている。

ペルソナは「ユーザーの多様性を理解するための思考ツール」として価値がある。しかし「ペルソナごとに別の記事を書く」ための分類として使う場合、粒度が細かすぎると逆に動けなくなる。「8人格のどの層をターゲットにするか」という問いが記事設計の都度生じ、判断を増やす。

6層への圧縮は「記事設計に使える解像度」を確保するための取捨選択だ。就学前の受験層と一般層は、同じ記事で書けるくらいには重なりが大きい。「全員を別々に満足させる」より「メインの層に刺さりながら他の層も排除しない」設計の方が量産できる。

EP-043（年齢フレーミング）で確定した「年齢帯を広く重ねる」設計と、このペルソナ圧縮は同じ方向を向いている。「厳密な分類より、広い包摂」という思想だ。

## 学び（一般化できるノウハウ）

1. **ペルソナは「使う道具の粒度」で設計する** — ペルソナは細かいほど良いわけではない。「この粒度で記事設計の判断ができるか」という使用目的から逆算して、必要最小限の人格数に絞る。

2. **サブペルソナは記事内のトーン差で吸収できる** — 「受験層向け」と「一般層向け」を別記事にするより、1本の記事で両方を意識したトーンと表現を使う方が量産効率が高く、SEO 的にも競合しない。

3. **機能より静的コンテンツで代替できないか確認する** — 診断機能のような動的な仕組みは実装・維持コストがかかる。「記事で同じ情報を提供する」静的代替を先に検討する。
