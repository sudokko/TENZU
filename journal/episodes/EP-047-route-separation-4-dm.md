# 経路分離・アプリ先行・4通DM構造への再々設計

## 何が起きたか（要約）

2026-05-08 に「フィードバック駆動型・4フェーズ構成」へ全面再構築済だった launch-plan のなかで、Phase 0 が「インフルDM経路」と「先行モニター経路」をバンドルしていることに矛盾が見つかった。1 通のDMでアプリ紹介＋モニター招待をバンドルすると、無名サイトでの「無償！」訴求が応募者の質を下げる。経路を完全独立化し、インフルへの接触を 4 通（1通目アプリ紹介／2通目お礼／3通目モニター案内／4通目クーポン配布）に分解、モニター募集は Phase 1 から開始、と再々設計した。

## 状況・背景

前日 2026-05-08 のセッションで HO-B2-25「先行価格＋プレローンチクーポン」を撤回し、フィードバック駆動型の 4 フェーズ構成（Phase 0/1/2/3）へ全面再構築した。新設した「TENZU 先行モニター制度」は 10 名前後・全 SKU 無償フルアクセス・本リリース時に「TENZU 開店記念ギフト」という、ChatGPT 原案の「軽いお礼 PDF」よりかなり重い設計になっていた。

翌日 2026-05-09、launch-plan の細部詰めをしている途中で、Phase 0 のインフル接触 DM が「アプリ紹介＋先行モニター招待」をバンドルしていることに気付いた。原案では「アプリを触ってもらう → 紹介してくれたらお礼 PDF」というシンプルな構造だったのに、モニター制度の重さがそのまま 1 通目の DM に乗っていた。社交辞令ゾーンの相手にまでモニター招待を打診する形になり、応募者の質を担保する仕組みが消えていた。

## やり取りの中身

最初に上がった論点は「読者向け価値（クーポン）と協力者向け価値（モニター）は同じ DM に乗せて良いか」だった。検討の結果、両者の対象も価値も異なるため経路を分離する方が自然と判断した。読者向け価値（クーポン）は「インフル経由で読者に流す」もの・協力者向け価値（モニター）は「インフル本人が能動的に応募する」もの。前者は受動的拡散、後者は能動的選別が機能する。

次の論点は「モニター募集をいつから始めるか」だった。Phase 0 から募集すると、商品ページもサイト本体も無い状態で「無償！」だけが先行することになり、価値理解の前にラッキー感が来てしまう。「価値理解（記事/商品確認）→ 無償ラッキー感」の順番でしか質の高いモニターは集まらないと判断し、募集開始は Phase 1（サイト本体オープン時）に後ろ倒しした。

3 つ目の論点は「インフルとの接触回数」だった。旧バンドル型では 2 回（1 通目バンドル＋紹介発生時お礼）だったが、価値の段階提示が機能しない。4 回に分解し、各回で別目的を持たせた：1 通目はアプリのみ紹介・実反応観察／2 通目は紹介発生時の即時お礼＋次回予告／3 通目は Phase 1 でサイトオープン案内＋モニター招待／4 通目は Phase 3 で本リリース＋読者向け「初回 1 本無料」クーポン配布。各回で対象を絞り込みながら接触を継続する構造になった。

DM 4 通目のクーポンは Stripe Promotion Code で実装する。1 SKU 100% OFF・コードあたり 30 回上限・60 日有効・1 人 1 回制限。コード命名規則は `[インフル識別子]-FREE`（例: `MAMABLOG-FREE`）。インフルが読者へ自発的に紹介してくれた場合に、ステマ規制対応として「TENZUより読者特典として提供されたコードである旨の明記」を依頼する建て付け。

## なぜそう判断したか

経路分離を選んだ最大の理由は「無名サイトでの『無償！』訴求は応募者の質を下げる」という認識だった。モニター制度の目的は集客＋ブラッシュアップであり、応募者の質が低いと両方の目的が達成されない。価値（記事・商品）を先に理解してから能動的に応募してきた人にだけ無償フルアクセスを提供する方が、フィードバックの質も高くなる。

アプリ先行（Phase 0 では商品ページもモニター応募窓口も非公開）にしたのは、無名サイトでの初接触は「重い参加要請」ではなく「軽い体験提供」が適切だからだ。アプリは完全無料・メアド不要・触ってすぐ価値が分かる。これを最初の接点にし、相手が能動的に紹介や具体感想を返してくれたら次の段階に進む、という段階的接触が無理がない。

4 通 DM 構造の論理は「観察 → 謝意 → 招待 → 提供」の階段だ。1 通目で実反応を観察、2 通目で謝意を即時表明、3 通目でモニター招待（協力者経路）、4 通目で読者向けクーポン配布（読者経路）。各段で相手の関与度に応じて接触を絞り込んでいくため、社交辞令ゾーンの人にまで重い招待を投げる事故が起きない。

## 学び（一般化できるノウハウ）

1. **「価値が異なるものは経路を分離する」** — 読者向け価値と協力者向け価値を 1 つの接点にバンドルすると、対象選別が機能しなくなる。経路を分けることで、各経路で自然な自己選別が働く。

2. **「無償！」訴求の順番** — 価値理解の前にラッキー感が来ると、応募者の質が下がる。無償提供を機能させるには「価値理解 → 無償ラッキー感」の順番が必要で、これは募集タイミングの設計でしか実現できない。

3. **段階的接触は対象絞り込みのフィルタになる** — DM を 1 通から 4 通に分解することは負担増ではなく、各段で相手の関与度に応じて接触を絞り込むフィルタになる。観察 → 謝意 → 招待 → 提供の階段は、社交辞令ゾーンを自然に振り落とす仕組みでもある。
