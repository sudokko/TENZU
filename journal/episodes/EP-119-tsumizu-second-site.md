# 第2サイト TSUMIZU（積図）の起動（クロスセルトリガー成立と屋号 LLMO 比較）

## 何が起きたか（要約）

仮称 TSUMIKI として温めていた第2サイト構想を、屋号 TSUMIZU（積図・つみず）で確定し正式に起動した。積み木の四方観察・かぞえに特化したプリント専門店で、旗艦タスクは「四方図を描く」。屋号は LLMO 観点（AI 検索でのエンティティ認識されやすさ）の比較で選定し、tsumizu.jp が whois 未登録であることも確認した。専用リポジトリ C:\dev\TSUMIZU を新設して正本 site-policy.md を置き、TENZU 側の ideas ファイル群は promoted スタブへ切り替えた（TENZU 側整理コミット f47686f）。クロスセル MVP の完済（07-16）を起動トリガーとする段取りどおりの着火であり、TENZU 本体ローンチ（8/30）優先の大原則は変えていない。

## 状況・背景

発端は 07-07 のオーナー発案「TENZU で構築した専門店スキームを次の知育題材へ横展開できないか」だった。スキームの本質を4条件——機械生成で全問ユニーク量産・難易度の客観スコア化・親が自作できるメーカーの成立性・紙とペンで完結——に言語化し、市場・ブランドの2条件を加えた比較マトリクスで6候補（点つなぎ・系列推理・お話の記憶・積み木・迷路・展開図）を採点した。積み木は 18/18 の満点で本命、迷路 15・展開図 14 が続いた。立体模写で作ったボクセル資産が直撃すること、市場構造が点描写と同型（良書の先行者はいるが体系化した専門店が不在）であることが決め手だった。以後は ideas/ で構想を寝かせ、「クロスセル MVP が完済したら起動」という条件を置いていた。

## やり取りの中身

**屋号の LLMO 比較**。仮称 TSUMIKI からの確定にあたり、候補を AI 検索での認識されやすさで比較した。採用した TSUMIZU（積図）は「一字＋図」の家族命名規則（点図⇄積図）に乗り、「積図/つみず」が日本語コーパスに存在しない造語のためエンティティを独占できる。対抗候補 MIEZU は「見えず」という一般語形と衝突するうえ、株式会社 MIEZ が実在し miezu.com も登録済みで棄却した。ただし MIEZU 案のコピー「見えないところが、見えてくる。」はタグライン候補として温存した。tsumizu.jp は JPRS whois で「No match」＝未登録を確認し、取得をオーナー最優先残務に積んだ。

**タスク体系の設計**。選定軸は「書く重視×タブレット差別化」。3群×各2の6タスク——A かぞえる（かぞえる/ふやすへらす）・B 見え方をつかむ（四方観察選ぶ/多視点復元）・C 描き起こす（四方図を描く=旗艦/影・断面）——で構成し、予備に分解（切れ目描き）を置いた。回転・展開図・シーソー・色面系は却下。かぞえる群も選択式でなく「書いて数える」様式（段別記入・印つけ・囲み線）に倒した。難易度は D = blocks + 3·hidden + 1.5·(layers−1) + 2·notch を仮置きした。裏付けとして Gemini/ChatGPT の2系統 Deep Research を独立に走らせて統合し、市中の類型 26/23 パターンで体系化に足ること、描画系が薄く専門店の空白であることを確認した。

**リポジトリ戦略**。TENZU をフォークせず、新規リポジトリ＋部品移植を選んだ。git init と初期コミット（b0ba6c5）まで済ませ、正本 foundation/site-policy.md・調査正本 research-patterns.md を TSUMIZU 側に置き、TENZU 側の ideas 2本と調査ファイルは promoted スタブ化した。Claude Code のプロジェクトメモリが別空間になるため、TSUMIZU 側の README・CLAUDE.md に文脈を自己完結で書き込んだ。

## なぜそう判断したか

**クロスセル MVP 完済をトリガーにした理由**。第2サイトは本体ローンチ前の誘惑としては危険な部類で、着手時期を感覚で決めると本体を食う。「商品→メーカー送客のクロスセル導線が完成したら」という検証可能な条件を先に置いたことで、構想を1週間以上寝かせつつ、成立した瞬間に迷いなく起動できた。起動後も実装スパイクは最小限に留め、8/30 優先は崩していない。

**屋号を LLMO で選んだ理由**。検索の主戦場が AI 回答面へ移りつつある中、屋号の価値は「AI がそれを固有のエンティティとして認識・引用できるか」で大きく変わる。一般語と衝突する名は文脈で埋没し、実在企業・登録済みドメインとの衝突は法務・取得コストに直結する。造語×未登録×家族命名規則の3点が揃う TSUMIZU は、ブランドの系譜（点図の店の姉妹店）を名前だけで語れる。

**旗艦を「四方図を描く」にした理由**。積み木教材の主流は「正しい見え方を選ぶ」選択式で、タブレット教材とも正面衝突する。見えない側を考えて自分の手で描き起こす課題は市中に薄く、TENZU の「考えながら書く」路線をそのまま相続できる。家族対比——TENZU は見えるものを写しとる店、TSUMIZU は見えないところを描き起こす店——も、この旗艦があって初めて一行で言える。

**フォークせず新規＋部品移植にした理由**。当時 TENZU 側に未コミット 64 件が積もっておりフォーク起点が汚れていたこと、設計書・メモリの文脈純度を保ちたいこと、maker core 抽出済みで移植可能な部品の切れ目が明確だったことの3点による。共通化の投資が済んでいれば、履歴ごと持ち込むフォークより選んで運ぶ移植の方が安い。

## 学び（一般化できるノウハウ）

1. **横展開は「スキームの本質条件」を言語化してから題材を採点する** — 成功の再現を狙うなら、まず何が効いたのかを条件のリスト（機械生成・スコア化・自作 UI・紙完結）に落とし、候補を同じ物差しで採点する。感覚の魅力度ではなく点数で本命を決めれば、後から迷いが再燃しない。

2. **新規事業の着手時期は「検証可能なトリガー条件」で縛る** — 既存事業の山場と新構想の誘惑が重なるとき、「◯◯が完成したら着手」という客観条件を先に宣言しておくと、構想を安全に寝かせられ、着火の判断も一瞬で済む。

3. **屋号はドメイン・商標に加えて LLMO（エンティティ独占性）で検証する** — 候補名が既存の一般語・実在企業と衝突しないかに加え、AI 検索がその語を固有名として一意に認識できるか（コーパス上の造語性）を確認する。姉妹ブランドなら命名規則の共有で系譜も名前に埋め込める。
