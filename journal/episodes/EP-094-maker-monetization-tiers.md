# メーカー有償化を2段階サブスクで設計する（深さは削るな・幅と量を絞れ）

## 何が起きたか（要約）

無料の「おためし点描写メーカー」をサブスクで有償化する設計を確定し、決済・認証・権限（entitlement）の基盤と模写の tier ゲートまでを実装した。3段構成——ゲスト（模写のみ・〜5×5・1枚3問・登録なし）／スタンダード ¥480（模写ぜんぶ・8×8・保存無制限）／フル ¥980（＋模写以外の全タスク＝鏡・回転・欠け補完・分解・立体）。貫いた原則は **「深さは削るな・幅と量を絞れ」**。コア体験（模写を1枚作って印刷する）は無料で完璧に動かし、絞るのは量産・所有・他タスクという「幅と量」だけにした。tier の差別化軸は最終的に「タスクの種類」に置いた——スタンダードは模写を深掘り、フルは全タスクを体験する。当初はグリッド上限で差をつけたが「フルのメリットが薄い」という指摘で調整した。認証は外部 JWT ライブラリ（jose）を入れず Node 標準 `crypto` の HMAC 自前署名にして依存追加をゼロにし、ロック UI は機能を「奪う」のでなくアップセルへ誘導する「発見」型にした。Stripe テストモードで申込→決済→ログインメール→tier 反転まで実証。¥980 フル（他タスクの製品化）は土台のみで一旦見送った。

## 状況・背景

メーカーは Phase 0 の無料 Web ツールで、親が PDF を印刷するためのジェネレータだ。一方 TENZU の本体は ¥200 一律のレベル別 PDF プリント（ローンチ 63 巻）。ここで最大の制約が **カニバリ（自己食い合い）回避**だった。メーカーが高機能すぎると、専門家が厳選したカリキュラムである PDF 商品が売れなくなる。だがメーカーを絞りすぎると CV 入口としての役割も果たせない。「無料で配って集客する道具」と「お金を取るサブスク」と「本体の商品」の3つを同時に成立させる線引きが要る。EP-087 で決済基盤（カート＋Stripe＋SES、DB なし）は通っていたので、その上に「継続課金で権限を出し分ける」層を乗せる段だった。

## やり取りの中身

設計は3AI 合議（Claude / Gemini / ChatGPT）で詰めた。「種類で課金する・2層の会員・単一パッケージ・カニバリ対策を打つ」までは全会一致で、割れたのは価格だけ（買い切り ¥500／サブスク ¥980／サブスク ¥500 ＋市場ベンチ）。無料を「3問・A4」まで絞る前提を共有した結果、全部入りを ¥980 に正当化でき、オーナー判断で **¥480／¥980 の2段階を初手から両方出す**形で握った。

**絞り原則の確定**。「深さは削るな・幅と量を絞れ」。模写を5×5で1枚作って印刷する、というコア体験は無料で完璧に動かす。絞るのは多面付け（4/6/12問）・大きい用紙・保存数・他タスクという「量と所有と幅」。用紙は「B4/A3 のサイズだけ有料化、A4 は縦横とも無料死守」にした。これはトップページの価値訴求③「家庭の印刷機に合わせられる」と矛盾させないためだ。並び向きは有料化せず詳細設定に隠すだけにした。

**tier の差別化軸をどこに置くか**。当初はグリッド上限で差をつけていた（ゲスト/エントリー 5×5・フル 6×6）。だが「フルのメリットが少なく見える」という指摘が出た。¥980 払う理由が「マス目が1段大きい」では弱い。そこで2段階で調整した。まずグリッド上限を両方 8×8 まで開放し（8 が実用上限——クリック式エディタの当たり判定が隣接中心間で重ならない最大）、スタンダードとフルのグリッド・保存・用紙を同値にした。そのうえで **差別化を `allTasks` 一点に集約**した（フル ＝ `{...エントリー, allTasks: true}`）。スタンダード＝模写を深掘り、フル＝模写以外の全タスク（鏡・回転・欠け補完・分解・立体）も使える、という本質的な価値差にし、tagline も「6×6まで」から「全タスク（…）まで、ぜんぶ。」へ変えた。当初付けていた点の大きさ制限も差別化軸から外し、ゲストでも小/中/大すべて使えるようにした。

**依存をゼロにした認証**。プランでは JWT ライブラリ（jose）を1つ足す想定だったが、実装では Node 標準 `crypto` の HMAC-SHA256 自前署名に切り替え、依存追加をゼロにした。Route Handler は Stripe SDK の都合で Node ランタイムが確定しているため標準 crypto で十分だ。cookie は二層の有効期限を持たせた——ログインは30日、tier の再検証は24時間。期限が切れたら Stripe へ照会して権限を取り直す。この照会は1人1日1回で済むので大規模でもレート制限に当たらない。DB は持たず、会員台帳は Stripe を単一のソースにする。

**実装範囲と実証**。新規で権限ゲートの SSOT（`capabilities.ts`）、署名 cookie の `auth.ts`、tier 解決の `billing.ts`、認証コンテキスト、API 6本（申込・検証・ログアウト・ログインリンク・自分の権限・課金ポータル）、価格／ログイン／アカウントの各ページを足し、`MakerApp.tsx` に tier を prop で受けてロック UI を出す改修を入れた。Stripe テストモードで価格2本を作り、申込→`checkout.stripe.com`→トライアル契約→ログインメールの実送信（SES）→検証→`/maker` へ307＋30日署名 cookie、まで実証した。途中の「メールが来ない」事象の真因はコードでなく、価格 ID 未設定で tier 解決が常にゲストになり契約者がゼロだったことだった。

## なぜそう判断したか

「深さは削るな・幅と量を絞れ」を原則にしたのは、フリーミアムで集客とカニバリ回避を両立させる線がそこにあるからだ。コア体験を削ると入口の魅力が落ち CV が死ぬ。逆に「量・所有・幅」は、ヘビーに使う人ほど欲しくなる軸なので、課金の動機になりつつ、軽い利用者の体験は損なわない。本体の PDF 商品とのカニバリは「メーカー＝非キュレーションの生成／PDF＝専門家の厳選カリキュラム」という UX の境界で切り、機能の絞り込みで切るのではない。

差別化を `allTasks` 一点に寄せたのは、tier の価値差は「量の多寡」より「できることの種類」のほうが伝わるからだ。「マス目が1段大きい」は説明しないと価値が分からないが、「鏡も回転も立体も作れる」は一言で違いが立つ。グリッドや保存数で小刻みに差をつけると各 tier の輪郭がぼやける。価値の境界を1本にすると、何を買うのかが明快になる。

依存をゼロにしたのは EP-027 以来の思想——足場は必要になってから足す。Node 標準 crypto で同じ署名検証ができるなら依存を増やす理由がない。これは「戻れる前提で一回やってみる」試行だったので、package.json を汚さないことが後戻りのしやすさに直結した。ロック UI を「発見」型にしたのは、剥奪のフレームか発見のフレームかで CV への効きが変わるからだ。「取り上げられている」でなく「上のプランで使える」と読ませる。

¥980 フルを土台のみで見送ったのは、段階を独立に着手できる形に切っていたからだ。決済・認証・権限基盤と模写の課金稼働が動けば、他タスクの製品化は後から足せる。SSOT 文書（decisions / pack-design）への反映も、戻れる前提の試行で確定文書を汚さないため、オーナーが「これでいく」と決めるまで意図的に保留した。

## 学び（一般化できるノウハウ）

1. **フリーミアムは「深さは削るな・幅と量を絞れ」** — 集客とカニバリ回避を両立させるなら、コア体験（一番やりたい1回）は無料で完璧に動かし、絞るのは量産・所有・付随機能という「幅と量」にする。コアを削ると入口の魅力が落ちて CV が死に、幅と量はヘビーユーザーほど欲しがるので課金動機として効く。本体商品とのカニバリは機能制限でなく UX の役割境界（生成ツール vs 厳選カリキュラム）で切る。

2. **有料 tier の差別化軸は「量」より「種類」に寄せると輪郭が立つ** — グリッド上限・保存数のような連続量で小刻みに差をつけると、各 tier の境界がぼやけて上位プランの理由が弱くなる。「できることの種類」（このタスクが使えるか）という質的な軸1本に寄せると、何を買うのかが一言で伝わり、アップセルの動機が明快になる。

3. **権限の出し分けに外部 JWT ライブラリは要らない** — 署名付き cookie で tier と有効期限を持たせる仕組みは Node 標準 `crypto` の HMAC で実装できる（Route Handler が Node ランタイムなら十分）。会員台帳を決済 SaaS に寄せて DB を持たず、cookie の有効期限を二層（ログイン長期・権限再検証短期）にして切れたら SaaS へ照会する。照会は1人1日1回規模なので大規模でも破綻せず、依存を増やさないほど「戻れる」実装になる。

4. **ロック UI は「剥奪」でなく「発見」のフレームで出す** — 無料ユーザーに見せる制限は、同じ機能でも「取り上げた」印象と「上のプランで使える」案内とで CV への効きが変わる。ロックアイコンからアップセルへ自然に誘導する見せ方にすると、不満ではなく上位プランへの興味を喚起できる。
