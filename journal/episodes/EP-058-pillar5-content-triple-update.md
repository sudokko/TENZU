# Pillar 5 本化と Content 三点同時更新（clusters/urls/pillars 全面刷新）

## 何が起きたか（要約）

案 H'' 反映の Content 領域全面刷新を実行した。Pillar 構造は 4 本 → 5 本へ拡張し（P5「親が子に寄り添う」を新設）、Cluster は 25 本 → 31 本（21 Cluster ＋ 3 FAQ ＋ 2 LLMO）へ再構成。content/clusters.md・content/urls.md・content/pillars.md の 3 ファイルを同時刷新し、SSOT カスケード（pillars → clusters → urls の波及）を漏れなく完了させた。主要変更は、C1-1「点描写 効果」を P4 旗艦 C4-1 へ移設（URL `/point-drawing-effects/` を維持して SEO 資産を継承）、C2-3「公文 算数 図形」30 の新設、C4-2「空間認知能力 鍛え方」30 啓蒙ハブの新設、P5 用途ハブの新設＋ C5-1「点描写 教え方」10、LLMO 専用 L-1「選び方完全ガイド」と L-2「家庭で育てる図形と空間認知 Q&A」の新設、LP-2「展開図 苦手」40 の受動拾い追加。同時に P4「710」VOL 内訳の再調査が不要であることを判定し、合算 810 で確定させた。

## なぜそう判断したか

判断軸は「Pillar 拡張は記事数増加ではなく責務分離である」という原則である。P5 を新設したのは記事を増やしたかったからではなく、「親が子に寄り添う」という責務が既存 P1-P4 のいずれにも吸収できなかったためだ。責務分離としての Pillar 増設なら、記事数制限（1〜2 本）を宣言することでスコープを守れる。

C1-1 → C4-1 の移設で URL を維持したのは、SEO 資産（既存インデックス・被リンク・直接流入）を捨てる損失が、URL 整合性のメリットを上回るためだ。スラッグだけ Pillar 名と不整合になるが、運用上の混乱は注釈で吸収できる。

LLMO 専用 L-1 / L-2 を新設したのは、EP-056 でゼロ群 62 ワードを「LLMO 専用領域のサイン」と読み替えた帰結である。クエリで戦わない領域を LLM 引用で迎え入れるためには、引用に最適化された専用記事が必要になる。SEO 記事と LLMO 記事を兼用させると、どちらの目的にも最適化できない。

P4「710」内訳の再調査を不要と判定したのは、合算が完全一致したためだ。タスクを残しておくと「未完了」として後続セッションを汚染する。判定で閉じられるタスクは即座に閉じる。

## 学び（一般化できるノウハウ）

1. **SSOT カスケード（pillars → clusters → urls の 3 ファイル波及）を必ず同時更新する**。Content 領域は 3 ファイルが SSOT として連結しているため、1 ファイルだけ更新すると参照リンクが切れ、整合が壊れる。影響範囲チェックリスト（3 ファイル）を事前に明文化し、実装忘れをゼロにする運用が必須。
2. **Pillar 拡張は「記事数増加」ではなく「責務分離」として扱う**。新 Pillar を立てるときは、責務が既存 Pillar に吸収できないことを確認し、記事数制限（1〜2 本など）を宣言してスコープ防御を行う。記事数の増加目的で Pillar を増やすと、運用コストが指数的に膨らむ。
3. **公文文脈ハイジャック対策で主軸クエリを差し替える**。「点つなぎ 次」0 vs「公文 図形」140 の決定的差を踏まえ、P2 主軸を「公文 図形」140 に置き換えた。実測ゼロのワードを主軸に据え続けると、Pillar 全体が無流入になる。
