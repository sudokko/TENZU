# 閉じると検証が全部止まる（プレオープン告知帯という第三の選択肢）

## 何が起きたか（要約）

ドメイン接続で tenzu.jp が誰でも見える状態になった。開店（8/30）まで Stripe 本番決済ほかが未完のため「内部からだけ見えるようにするか」を検討し、**封鎖しない**を選んだ。代わりに全ページ最上部へプレオープン告知帯を出し、購入導線は止めない。制御は env `PREOPEN` 一本で、**未設定＝出る**が既定。開店当日に `PREOPEN=0` を設定して再ビルドすれば消える（decisions §3.109）。同日、`check-env-gates.mjs` で本番 index / staging noindex を両方向確認し、**開店ゲート G4 を通過**した。

## 状況・背景

Amplify のアクセスコントロール（Basic 認証）を使えば、コンソール 3 分・コード変更ゼロで確実に閉じられる。しかし閉じた瞬間、**Stripe webhook・メール送信・GA4・Search Console の所有権確認が全部 401 で止まる**。いま必要なのは正にその本番検証で、手段が目的を殺す構図だった。

もう一つの理由はインデックスの助走。新規ドメインは評価が付くまで数週間かかる。開店 8 日前に閉じて 8/30 に開けるのは、SEO 的にはスタートを 8 日遅らせるのと同じである。

## やり取りの中身

**告知帯の文面**。「ただいまプレオープン中です。正式オープンは 2026年8月30日。決済まわりを動作確認中のため、ご購入は 8/30 からお願いします。」購入導線は止めない——テストキーの間は実カードが通らないので実質売れないし、止めると自分の検証まで止まる。

**語彙は「工事中」を使わなかった**。壊れている印象を与えるうえ、確定した開店日があるなら告知は期待醸成に転じられる。ブランドの Voice としても「プレオープン」を採る。

**SEO 事故を 2 重に防いだ**。①告知文を title / description / OG / H1 に一切載せない——載せると開店後もしばらく検索結果に「準備中」が出続ける ②帯は DOM 最上部に来るため `data-nosnippet` を付けてスニペット候補から外す。

**既定を事故側に倒さなかった**。`PREOPEN` 未設定＝帯が出る。EP-125 の `IS_PREVIEW` と同じ思想で、「開店したのに帯が残る」より「まだ準備中なのに帯が無い」ほうが害が大きい、という向きで既定を決めた。

**スマホでは PRE-OPEN チップを落とした**。チップを残すと 375px 幅で 4 行・100px 超になりファーストビューを食う（実測: デスクトップ 39.7px / 375px 幅 81.8px）。

## なぜそう判断したか

**「閉じる／開ける」の二択を疑った**。閉じれば検証が止まり、そのまま開ければ未完成の決済を晒す。どちらも受け入れがたい。第三の道は「**開けたまま、状態を宣言する**」ことだった。訪問者に対して誠実で、検証も止まらず、インデックスの助走も進む。

**開店当日の作業を設計と同時に書いた**。env はビルド時に焼き出す設計なので、値を保存しただけでは消えない。この解除手順を判断ログ・開店ゲート G4・TODO の 3 か所へ書き込んだ。EP-125 で学んだ「フェイルセーフの向きを決めたら、その代償を運用ゲートへ書く」の適用である。

## 学び（一般化できるノウハウ）

1. **「隠す」は検証を止める。状態の宣言で代替できないか考える** — 未完成を隠す手段は、たいてい外部連携も一緒に止める。閉じずに「いまどういう状態か」を伝えるだけで済む場合が多い。

2. **一時的な表示は、消し忘れの害と出し忘れの害を比べて既定を決める** — どちらへ倒れても損害が出るなら、**大きいほうを防ぐ側**を既定にする。ここでは「消し忘れ」より「出し忘れ」が重かった。

3. **一時的な文言をメタデータへ入れない** — title・description・OG に入れた文言は、消しても検索結果にしばらく残る。期間限定の表示は本文の中だけに留める。
