# MailerLite 運用方針（フル Automation 採用）と専門性活用の枠組み

## 何が起きたか（要約）

C-3 サービスブループリントのメール運用設計で、Claude が最初に提案した「リスト保管のみ・配信運用なし」の軽量案を、CRM ベンダー営業 12 年のメールマーケ専門家であるユーザーが即座に訂正した。「Automation はフルシナリオ組んでも初期設定が重いだけ、運用は自動化される。初期投資と運用負荷を分離して考えるのがプロの視点」という一言で方針が転換し、ウェルカム・F2/F3 転換・非アクティブ復活・カート放棄リカバリまでを含むフル Automation 運用が採用された。

## 状況・背景

C-3 の設計フェーズで、MailerLite の位置付けを決める論点（❓4）が議論になった。TENZU は Stripe 決済でメールアドレスを取得するため、そのリストをどう活用するかという問いだった。

Claude の初期判断は「個人運営であれば配信運用にかける時間が取れない。リスト保管だけしておき、本リリース通知のみ送ればよい」というものだった。MailerLite に Automation シナリオを組む作業は工数が重いと判断し、「まずは箱だけ確保、運用は後回し」を推奨した。

これに対しユーザーが「俺、実はメールマーケはプロ」と発言した。CRM ベンダーでの 12 年間の営業経験から、MailerLite Automation の初期設定・シナリオ設計・効果測定まで自分で回せる知識と経験を持っていた。

## やり取りの中身

### 訂正の骨子

Claude が「シナリオ 1 本だけ復活させる B 案（F2 転換メール 1 通）」を提案したとき、ユーザーから「シナリオ一本っていうほど甘くはない。どうせならフルシナリオやる。初期重いだけで運用は自動化される」という返答があった。

この発言の核心は「初期投資コストと運用コストを分離して評価する」という考え方だ。Claude は「Automation は運用が重い」と捉えていたが、プロの視点では逆で、Automation はむしろ運用を自動化するために設計するものだ。初期設定のコストは確かに高いが、一度組んでしまえば以降の運用は自動で回る。

### 採用したシナリオ構成

最終的に採用したフルシナリオ：

| シナリオ | トリガー | 目的 |
|---|---|---|
| ウェルカムシリーズ | 先行モニター登録時 / 本リリース通知登録時 | 初期関係構築・使い方ガイド |
| F2 転換 | 初回購入後 30 日非購入 | 2回目購入促進 |
| F3 転換 | 2回購入後 60 日非購入 | ヘビーユーザー化 |
| 非アクティブ復活 | 30 日 / 90 日開封なし | 休眠顧客再獲得 |
| カート放棄リカバリ | Stripe 未決済セッション検出 | 離脱ユーザー回収 |
| レビュー収集連動 | 購入後 7 日 | Google Forms へ誘導 |

MailerLite を選んだのは、個人運営が使いやすい UI・Automation 機能の充実・HubSpot や Klaviyo と比較したコスト感の三点が根拠だった。

### 分業設計の確定

「メールマーケはユーザーが主担当・Claude が枠組み整備の補助役」という分業を設計書に明記した。シナリオの内容設計（文言・ターゲティング・A/B テスト）はユーザー主導で進め、Claude はテンプレートフレームや設計書への反映を担当する。

この分業設計を次セッション以降でも維持するため、`feedback_email_marketing_expertise.md` を memory に新設した（→ EP-005）。

## なぜそう判断したか

Claude の汎用的な「初心者向け配慮」は、専門性を持つユーザーにとって的外れなアドバイスになる。「個人運営だから軽量に」という一般論は、CRM のプロにとっては「素人扱い」に映る。

専門性がある領域では、AI が「難しいからやめておけ」と言うべき場面ではなく、むしろ「どう組むか」の設計論の相手になるべきだ。MailerLite Automation の場合、初期設定は確かに重いが、それは専門家が得意とするフェーズであり、設定後の運用は完全自動化される。プロが初期設定を担う構造であれば、フルシナリオ採用は個人運営でも現実的な選択肢になる。

メール運用はブランドとの継続的な接点を作る機能であり、TENZU のリピート率・LTV に直結する。ここで妥協すると、ブランド接点の質が恒久的に下がる。専門性の高い領域こそ、スケールした投資が長期的に効く。

## 学び（一般化できるノウハウ）

1. **専門性のある領域は AI 提案レベルを引き上げる** — AI の汎用提案は「平均的な初心者」を想定している。専門知識をフィードバック memory に記録すると、以降の提案の前提が変わる。

2. **「初期投資コスト」と「運用コスト」を分離して評価する** — 「初期重い＝長期的に重い」は誤りの場合が多い。Automation に限らず、設定が重く運用が軽い仕組みは個人運営で積極的に採用できる。

3. **得意領域はスケール投資、不得意領域は割り切り** — 個人運営の最適化は「何をやるか」と「何をやらないか」の二軸で決まる。得意領域に経営資源を集中するために、不得意領域の割り切りが対になって必要。
