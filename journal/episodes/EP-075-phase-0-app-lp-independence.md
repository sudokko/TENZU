# Phase 0 LP 独立化（販売 LP デチューン版を破棄し、アプリ専用 LP として新規作成へ）

## 何が起きたか（要約）

D2 LP v3.1 が完成した翌日、Phase 0 用の LP を「本体 LP のデチューン版（販売要素を隠す）」として作る構想に立ち止まり、**完全独立のアプリ専用 1 枚 LP** として新規作成する方針に変更した。理由は「Phase 0 = 4 通 DM 1 通目『アプリ使ってみて』の着地点であり、販売文脈混在は紹介しづらく DM 文脈も濁る」。販売・SKU・FAQ・モニター・受験訴求は全部出さない／構成 5-7 セクション（Hero / 機能 3 カード / 30 秒デモ / 使い方 / 点描写とは簡潔版 / About / CTA 再掲）／URL 想定 `app.tenzu.〇〇` または `/app`。販売サイト本体 LP（v3.1）は Phase 1 まで非公開で温存。Priority Guide（phase-0-app-lp-guide.md）を新設し、Claude Design で叩き台 2-3 案を発注する段取りに変えた。

## 状況・背景

D2 LP v3.1（販売サイト本体 LP）は 2026-05-14 に完成しており、商品紹介・記事一覧・FAQ 抜粋・モニター応募導線・受験訴求まで一通り盛り込まれた完成度の高い状態だった。当初、Phase 0（アプリ＋最小 LP＋初期記事 10 本のみ公開）でも、この本体 LP を「販売要素を CSS で非表示にしたデチューン版」として流用する想定だった。

2026-05-15 のセッション冒頭、Phase 0 LP の構造を詰めていた段階で、4 通 DM 1 通目の文脈との齟齬が浮上した。1 通目 DM は「アプリ使ってみて」が主旨で、販売・モニター招待は一切言及しない（経路分離の原則）。その着地点として販売 LP のデチューン版を見せると、ユーザーは「販売文脈の隠された痕跡」を視覚的に感じ取り、DM の純粋な「アプリ紹介」文脈が濁る。

## やり取りの中身

最初に上がった論点は「デチューン版で本当に成立するか」だった。本体 LP は商品ページ・カート・FAQ・モニター応募・受験訴求がレイアウトの骨格として組み込まれており、これらを CSS 非表示にしてもナビ構造・H1 のメッセージング・ファーストビューの配色が「販売サイト感」を残す。Phase 0 の着地点としては「販売前提だが今は隠している」という二重メッセージになる。

次の論点は「アプリ専用 LP の独立化で何を捨てるか」だった。独立化すると、本体 LP の以下を全部出さない：販売・SKU・FAQ・モニター・受験訴求・記事一覧の網羅版・商品比較表・価格表。残すのはアプリの紹介・使い方・点描写の簡潔説明・About のみ。情報量は本体 LP の 1/3 程度になる。

3 つ目の論点は「URL 構造をどうするか」だった。本体 LP は `tenzu.〇〇`（販売サイトのトップ）、アプリ LP は `app.tenzu.〇〇`（サブドメイン）または `/app`（パス）の 2 案。サブドメイン案は経路完全独立・SEO 上もアプリ評価がトップに影響しない／パス案は実装簡単・OGP 設定が一元化できる。判断は別セッションに持ち越し、まずは Priority Guide で「URL 想定 `app.tenzu.〇〇` または `/app`」と両論併記した。

4 つ目の論点は「販売サイト本体 LP（v3.1）をどうするか」だった。完成しているのにすぐ公開しないのは惜しいが、Phase 1（サイト本体オープン期）まで非公開で温存する判断にした。完成度が高いまま温存できるのは利点で、Phase 1 開幕時に即公開できる状態にしておく。

Priority Guide（`docs/design/phase-0-app-lp-guide.md`）を新設し、以下を明文化した：
- Phase 0 LP の役割（4 通 DM 1 通目の着地点・アプリ訴求のみ）
- 構成 5-7 セクション（Hero / 機能 3 カード / 30 秒デモ / 使い方 / 点描写とは簡潔版 / About / CTA 再掲）
- 出さないもの（販売・SKU・FAQ・モニター・受験訴求）
- 残すもの（アプリ紹介・使い方・点描写の簡潔説明・About）
- URL 想定（`app.tenzu.〇〇` または `/app`）
- キービジュアル方針（実スクショ優先・画像生成 AI 禁止）

次アクションは Priority Guide をもとに Claude Design で Phase 0 アプリ LP の叩き台 2-3 案を発注。あたしが量産・あんたが選定するハイブリッド運用。並行してアプリのキービジュアル・デモ素材を実スクショで用意する。

## なぜそう判断したか

デチューン版を破棄したのは、DM 文脈との齟齬が「販売前提を隠している感」として読者に伝わるリスクが許容できなかったからだ。経路分離（インフルDM 経路と先行モニター経路の完全独立化）の原則は、DM 1 通目で販売・モニター招待を一切混ぜないことで成立している。LP がその原則を視覚的に裏切ると、経路分離設計の意味が消える。

販売サイト本体 LP（v3.1）を温存する判断は、「完成したのに公開しない」コストよりも「Phase 0 で販売感を出すリスク」の方が大きいと評価した結果だ。Phase 1 開幕時に即公開できる状態を維持することで、完成度の高い LP を 4-6 週間後にフレッシュなまま投入できる。

URL 構造の判断を保留したのは、サブドメイン案とパス案の評価が「実装容易性 vs 経路独立性」のトレードオフで決着しないからだ。アプリ本体の技術選定（Next.js / Amplify のルーティング設計）と連動する判断のため、D5/D6 フェーズで決める方が情報が揃っている。Priority Guide には両論併記し、当面の判断保留を明示した。

Priority Guide を新設したのは、構成判断（5-7 セクション・出すもの／出さないもの・キービジュアル方針）を Claude Design の発注前に確定させるためだ。発注時に「迷い」が残っているとAI生成が方向感を欠く。判断を Priority Guide に集約して、発注時はそれをそのまま渡せる状態にする運用。

## 学び（一般化できるノウハウ）

1. **「デチューン版」は元の文脈を残す** — 完成したものから要素を CSS 非表示で削るだけのデチューン版は、レイアウト・配色・ナビ構造に元の文脈が残る。「販売前提を隠している感」として読者に伝わるため、文脈を完全に切り離したい場合は独立設計が必要。

2. **完成度の高い成果物の「温存」は選択肢** — 完成したものを即公開しない判断は無駄に見えるが、フェーズ設計上「投入タイミング」がコストを上回る価値を持つ場合がある。完成度を維持したまま 4-6 週間後に投入する選択肢を常に持つ。

3. **発注前に「迷い」を Priority Guide に集約する** — AI 生成ツールへの発注は、判断が確定してから行う方が成果物の質が上がる。発注前のセッションで Priority Guide に判断を集約し、発注時はそれをそのまま渡せる状態にする。発注時に迷いが残ると AI 生成が方向感を欠く。
