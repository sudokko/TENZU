# 広告連動バンドル確定と春 LP/PR TIMES ドラフト前倒し

## 何が起きたか（要約）

2026-07-17、開店後の宣伝本格化に向けた3タスクを1セッションで完了した。①広告と連動するバンドル SKU の確定（2本＋将来枠・decisions §3.80・pack-commerce §24 全面書き換え）、②春需要期向け LP と PR TIMES リリース文のドラフト前倒し（docs/drafts/spring-lp/）、③レベル選びガイド結果画面→SKU 詳細 #preview の配線（funnel §3.5 の唯一の未配線エッジ解消）。調査では個人事業主が PR TIMES の無料枠対象外（1件¥30,000税別）と判明し、代替3択を添えてオーナー判断に委ねた。3タスクともオーナー全面OKを経て、07-18 にコミット e31bea6 として確定した。

## 状況・背景

ローンチ体系は 07-11 のピボットで T=0＝2026-08-30 の単一開店＋宣伝2段化に確定し、宣伝本格化の最大の山は春（2〜4月）の入学準備スパイクになる。単品¥200 では広告費が回収できないことは獲得設計のゼロベース見直しで判明済みで、広告の受け皿には客単価を引き上げるバンドルが必要だった。バンドル構想は初期からあったが、SKU としての構成・価格・実装方針は未確定だった。春 LP と PR は 10〜11月の仕込みタスク予定だったが、文章ドラフトはコードと違い前倒ししても腐りにくい。この回は「Fable 3日間作戦」のセッション2として、まとめて前倒しした。

## やり取りの中身

**バンドルは2本＋将来枠に絞った**。春枠「入学準備プリント 7 枚セット」¥1,100（春スパイク期・春 LP の主オファー）と、通年枠「年長さんのはじめの 5 枚」¥800（メーカー完了画面からの常時導線）の2本を確定し、「公文の次に」「見取り図導入」は実売を見てから判断する将来枠に送った。旧案「春のタスクコンプリートセット」は春枠との二重オファーとリスク語「コンプリート」を理由に不採用・統合。単位定義は「枚＝巻（1 SKU・12問 PDF）」に正し、価格式を巻数×¥200×(1−20%)・¥100未満切り捨てへ統一した。7巻構成の正本は funnel §10.3 に一本化し、バンドル側は参照のみ（二重記載禁止）。構成は全巻3×3の「形を写す3＋位置を動かす3＋重ねる1」＝訴求軸「形と位置」と相似形。¥1,000 心理上限は単品文脈と整理し、バンドルは広告回収下限以上の別レンジとした。クーポン併用は不可（Stripe の allow_promotion_codes を付けない＝実装ゼロ）。

**Stripe 実装は設計だけ確定して10〜11月へ送った**。既存の price_data 動的生成を踏襲し（別商品 ID 登録は不採用）、1 line item＋metadata.skus に構成巻を CSV 展開する方式にした。これで既存のサンクスページ復元・再 DL メールが無改修で動く。実装は春仕込みの10〜11月とし、準備期はコードを書かない方針を守った。

**春 LP と PR TIMES はドラフト全文まで作った**。lp-plan.md には構成7セクション・SEO 見出し表・コピー初稿全文・Voice チェックリスト・未決事項（LP スラッグ・サブ CTA 先など）を、pr-times-draft.md にはタイトル3案・リード・本文全文・画像5点仕様・会社概要雛形・配信チェックリストを納めた。LP 骨子は kicker＝業態識別句、H1「入学準備ドリル｜春から始める形と位置の練習」、「空間認知」は本文初出のみ（Hero・見出し禁止）・「入学までに」型ゼロ・バンドル CTA は最終セクション1箇所。調査で PR TIMES の無料枠（スタートアップチャレンジ）は設立24ヶ月以内の株式会社限定で個人事業主は対象外＝従量1件¥30,000税別と判明し、①12月に実費配信②春 LP 公開の1月に集約③valuepress 等の代替、の3択をドラフトへ記載してオーナー判断に委ねた。

**ガイドの死リンクを #preview 配線で解消した**。レベル選びガイド結果画面の href="#" の死リンクを、live 巻のみ /products/{sku}#preview へ飛ばす「問題の中身を見る →」ボタンに置き換えた。SKU 詳細側にはアンカー id と scroll-margin-top を追加し、scaffold 巻ではボタンを出さない。build/tsc と実機（アンカー着地・モバイル横スクロールなし）で検証し、funnel と screen-flow の設計書も同期した。

## なぜそう判断したか

**バンドルを2本に絞った理由**。同じ時期に似たオファーが2つあると、比較コストが生じて両方の CV が落ちる。春枠と通年枠は出る場所（春 LP／メーカー完了画面）と時期が重ならないから併存できる。3本目以降は将来枠として確定を先送りし、その判断自体を記録した。

**構成の正本を funnel §10.3 に置いた理由**。バンドルの構成巻は導線設計と価格設計の両方が言及したくなる情報で、二重記載すると改訂時に必ずズレる。正本を funnel に定め、pack-commerce は参照のみとした。

**ドラフトを前倒しし、実装を送った理由**。LP コピーや PR 文面は事実が変わらない限り腐らないが、コードは書いた瞬間から保守対象になる。準備期は問題量産が最優先で、保守物を増やさない。だからドラフトは弾込めとして前倒しし、Stripe 実装は設計だけ残して春仕込み期に送った。

**PR TIMES の前提を今調べた理由**。「無料枠で配信できる」前提のまま12月を迎えると、直前に¥30,000 の予算判断を迫られる。ドラフト段階で制約を洗い出し、3択を落ち着いて比較する時間をオーナーに渡せた。

## 学び（一般化できるノウハウ）

1. **繁忙期の弾は閑散期に込める——ただし文章だけ** — LP コピーや PR 文面のような劣化の遅い成果物は数ヶ月前倒しできる。コードは書いた瞬間から保守対象になるため、実装方針だけ確定して着手は使う直前に置く。前倒しの対象は成果物の劣化速度で仕分ける。

2. **外部サービスの「無料枠」は自分の事業形態で使えるかを最初に確認する** — 無料枠には法人格・設立年数などの適用条件が付いていることがある。利用計画に組み込む前に条件を原文で確認し、対象外なら代替案と費用をセットで意思決定者に渡す。

3. **複数文書が欲しがる構成情報は正本を1箇所に決めて参照させる** — バンドル構成のように導線設計と価格設計の両方に関わる情報は、二重記載すると改訂でズレる。正本の置き場所を決定として明文化し、他文書には参照のみ・二重記載禁止と書いておく。
