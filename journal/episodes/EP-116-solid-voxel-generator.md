# 立体模写のボクセル生成器 v1（自由線試作からの脱皮・Lv.5 拡張で6巻化）

## 何が起きたか（要約）

立体模写の作問を、自由線エディタでの手描きからボクセル生成器 v1 による量産へ切り替えた（2026-07-16・decisions §3.78）。オーナー発案「3D を組んでから投影する」に沿い、単位立方体の集合で立体を構成して斜投影（右上45°）の実線・点線を自動導出する生成器 gen/solid.ts を新設。既存の生成器レジストリに配線したため、atelier の「候補を追加生成」ボタンが立体巻にもそのまま生えた。同日、オーナーの「Lv.10 くらいまで複雑な設問を」という要望を、外向け Lv.5 固定の原則を守ったまま Vol 増設で吸収し、立体ラインを3巻から6巻へ拡張（Lv.5 に Vol.2〜4 を増設）。候補は lv3=26／lv4=24／lv5=26 問、増巻分は vol2=30／vol3=23／vol4=20 問を投入した。コミットは 07-18 の 21a970d、設計書 pack-tasks §22.3 への反映は 07-26 の f535195。

## 状況・背景

立体模写には方式転換の歴史がある。最初の試作はボクセル積み木式のエディタ（等角投影）だったが、参考ワークブックにある四角すい・八角柱・切り欠き立方体——頂点が格子上を自由に動く立体——が原理的に作れず、オーナー判定「イマイチ」で棄却された。次に 06-30、模写メーカーの描画機構（点クリック→任意方向の線分）をフォークした自由線エディタ /maker-solid を実装し、07-01 に正式メーカー化・atelier 問題化・「ブロック」概念を全廃した難易度再設計（隠れ辺を最大ドライバーとする式）まで整えた。開店時ラインは Lv.3〜5 各1巻の混合3巻構成。以降は手描きと、AI が座標を直接計算する押し出しスクリプトで約60個の種を作っていたが、各巻12問を賄いつつ難易度の天井も上げるには、量産の仕組みが要る段階に来ていた。

## やり取りの中身

**ボクセル→投影→稜線抽出のパイプライン**。生成器はボクセルで3D を構成し、確定済みの斜投影（右上45°・アイソメ化はしない）へ落とし、周囲4セルの占有パターン（1凸・3凹・対角2鞍）から折れ目稜線を抽出、隠線判定とマージを経て SolidEdge[] を出力する。全単位格子＋45°の組み合わせでは「単位辺は全可視か全隠蔽か」が成立するため、隠線判定は単位辺の中点1点に対する閉区間被覆と、2倍整数化した厳密な深度比較で済む。縁が重なる奥辺は実線優先で点線を破棄する。

**レジストリ配線とラダー駆動**。gen/index.ts の kind に solid を追加し、ladder.json に solid セクション（隠れ辺 none/some/full＋D 窓）を実体化した。生成器はレジーム別プロファイル（盤面・ボクセル空間・形族・対称率・クォータ）で補完されるため、atelier で D 窓を編集すると生成が追従し、Vol 追加もラダー追記だけでできる。形族は box/stack/steps/poly/wall/carve/compose/grow の8種。目視 QA はコンタクトシートの PNG 化で行った。

**品質フィルタはイテレーション2回の学習で決めた**。①完全直方体クォータ（ランダム成長の密集収束や対称化の埋め戻しで「ただの直方体」へ退化する対策）②視線整列で線が潰れる形の除外③Lv.5 の点線/実線比の上限（濁り防止）④平板排除の最低高さ⑤Lv.4 の「隠れ辺すこし」は最長優先でなく実線端点アンカー＋連結ペア優先（脈絡なく浮く点線を防ぐ・背面コーナーの L 字が正解）⑥平行移動不変の形シグネチャによる巻内かぶり除外。carve（角欠き）への対称化は、鏡像が欠きを埋め戻して直方体に退化する事故があり適用外にした。

**Lv.5 拡張と同日の追加改修**。増巻分は D 窓の上限から生成プロファイルを自動導出する仕組み（XL/XXL）にし、城砦様の複合形などで D110〜312 を実測した。atelier には「点線（隠れ辺）なしモード」も追加し、採用時に点線を物理削除して D を焼き直す経路を既存 API のまま通した（点線フルの D170 級が D50 級まで落ちるため、D 窓の再較正は検品時のオーナー判断とした）。

## なぜそう判断したか

**棄却したはずのボクセルを生成に復活させた理由**。かつてのボクセルはエディタとして棄却された——描きたい立体を表現できなかったからだ。今回はボクセルを生成専用に限定し、エディタは自由線のまま残した。同じ技術でも「入力の道具」と「量産の道具」では要件が違う。生成はボクセルが表現できる範囲だけを量産すればよく、表現の天井は手描き側が担保するから競合しない。

**手描きを先行させたことが効いた理由**。手描きと種作りの期間に、投影の一貫性・隠れ辺の正しさ・内部線を描かない、といった作問 QA 基準が言語化されていた。生成器の品質フィルタはこの蓄積の写像である。構造を知らないまま最初から自動化していたら、何を除外すべきかを決められなかった。

**Lv 追加でなく Vol 増設にした理由**。外向けレベルは5段階固定が原則で、難易度の細かさは Vol で吸収する設計になっている。「Lv.10 相当」の要望も D 窓の高い Vol を増やせば表現でき、対外のレベル体系という約束を壊さずに済む。

**D の伸ばし方を体積から特徴数へ変えた理由**。大きな箱を作っても稜線はマージで数本に潰れ、D は体積では伸びない。胸壁の刻みのような折れ目＝特徴を増やすことが D を上げる道になる。ただし特徴を増やすと視線整列も量産されるため、大型プロファイルだけ整列許容を緩め、実線優先の重なり処理で描画整合を守った。

## 学び（一般化できるノウハウ）

1. **手で作って感覚を掴んでから自動化する** — コンテンツ量産は、まず手作業で作って品質基準を言語化し、その基準をフィルタとして生成器に写す順で進める。生成器の品質は探索アルゴリズムではなく、手作業期に蓄積した除外条件の質で決まる。

2. **棄却した技術は「何として棄却したか」を精確に記録する** — ボクセルはエディタとしては失格でも、生成器としては最適だった。棄却理由を用途と結び付けて記録しておくと、別用途での再利用判断が速くなり、過去の判断とも矛盾しない。

3. **生成器は単発スクリプトにせずレジストリとパラメータ表へ接続する** — 生成ロジックを kind の一覧とラダー定義に配線すれば、UI ボタン・難易度窓の編集・巻追加が既存の仕組みのまま効く。「巻を足す＝定義を1行足す」まで下げると、増巻の限界費用がほぼゼロになる。
