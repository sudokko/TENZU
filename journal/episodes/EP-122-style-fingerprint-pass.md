# 文体指紋パスの新設（AI 癖の定量全廃・頻度予算制）

## 何が起きたか（要約）

オーナーの「記事全体に AI が書いた臭が漂う」という相談を起点に、AI 併用執筆の記事に残る文体上の癖＝「文体指紋」を定量把握して除去する仕組みを作った。content/revision-craft.md に §3.6「文体指紋パス」を新設し、全角ダッシュ「——」と禁止語「置く」「静か」系は0（全面禁止）、反転リフレーム・リズム三連・独自比喩・同型キメは頻度予算制というルールに制度化。公文記事でのパイロットを経て全19本へ一括適用した。コーパス計で「——」92→0、「置く」全活用37→0、「静か」系は計9→0、タグライン変奏三連は全廃。drafts と公開版が乖離していた6本は web→drafts へ逆同期して19ペア完全一致に戻し、コミット 4aaa515 として push した。さらに生成・推敲・検査の3層へ同ルールを配線し、新規記事にも効く形にした。

## 状況・背景

正規記事は約20本体制で、構成→本文化→推敲の craft 3冊に沿って Claude が書き、オーナーがレビューする分業になっている。品質検査（article-reviewer）は NG 語や構成の逸脱を検出していたが、「どの記事も同じ筆者の同じ癖で書かれている」という均質さ自体は検出対象になかった。オーナーからは当初「パーソナリティ（囲碁・バドミントン・娘2人の父・IT/マーケ業界の経歴）を織り交ぜたい」という方向も提示されており、対策の選択肢は文体規制の一本ではなかった。

## やり取りの中身

**対策候補4つを捨て、指紋除去一本に絞った**。体験素材の織り込みは「うちの子らは優秀だったので体験素材がほぼない」という理由で不採用。実物写真への差し替えはページ重量と手間で不採用。著者ボックスと図版の自前化はオーナーが明示的に不採用。decisions.md の判断ログを制作裏話として織り込む案は、note の開発実録連載のネタとして温存するため不採用。採用は「文体癖の頻度規制」のみとなった。

**§3.6 は0禁止と頻度予算の2階建て**。「——」は当初2箇所まで許容の設計だったが、オーナーの「これ AI っぽい」で0に改定。禁止語「置く」（全活用形・alt 含む記事全体。「位置」「配置」等の熟語と補助動詞「〜ておく」は対象外）と「静かに」も0。一方、反転リフレーム「A ではなく B」はキー主張の同一ペア再掲を予算外としたうえで別ペア2箇所まで、リズム三連は1箇所まで（タグライン変奏三連は0）、独自比喩は1系まで（コールバックは可）、同型キメは各1回という予算制にし、修辞そのものは殺さない。検出手順は「機械 grep→目視→数えてから直す」。git bash の grep は日本語の文字クラスをバイト単位で誤検出する（「置[く…]」が「位置・」に当たる）ため、「置」の全ヒットから熟語を目視除外して数える手順も §3.6 に明記した。

**パイロット→6並列で一括展開**。公文記事で実測「——」11→0・「置く」8→0・「静かに」3→0・反転構文9→2を確認し、オーナーの読み味 OK を得て即日横展開。パイロット済みの1本を除く18本を、drafts 編集→web 同期の12本と、当時乖離していて web 側のみ編集の6本に分けてサブエージェント6並列で処理し、オーケストレータの最終スイープで取り残し2件（三連の残存など）を検出・修正した。リード書き出しの文型かぶり（「『クエリ』で調べる方の多くは」3記事、「このページは」2記事）も各1本へ解消した。

**禁止拡大とパイプラインへの配線**。後半でオーナーが連体形「静かな」にも AI 臭を指摘し、「静か」系全形を0へ拡大（該当2箇所を修正し計9→0）。乖離6本は web→drafts へ逆同期して19ペア完全一致に戻した。さらに writing-craft §3.0 に「文体指紋を最初から出さない」を追加し、article-reviewer に観点 M「文体指紋」を新設。本文化（出さない）→推敲 §3.6（消す）→レビュー観点 M（検出する）の3重ゲートとして新規記事にも効く形に配線した。next build と llmo-check 19本 ERROR 0 を確認してコミットした。

## なぜそう判断したか

**パーソナリティ織り込みではなく指紋除去を選んだ理由**。体験談は素材がなく、書けば捏造リスクになる。写真・図版・著者ボックスはコストと重量が増えるわりに、AI 臭の根本である文の癖には効かない。対して文体指紋は grep で数えられ、消せたことを機械的に確認できる。検証可能な一本に絞った。

**0禁止と頻度予算を分けた理由**。「——」や「置く」は個々の使用が自然でも、コーパス全体で92回・37回と反復されると筆者の指紋になる。これらは存在自体を禁止して初めて消える。一方、反転リフレームや三連は修辞として本来有効で、全廃すると文章が平板になる。「いちばん効く1箇所を残して他を開く」予算制が品質と個性のバランス点だった。

**印象論を数に変えた理由**。「AI っぽい」は主観で、議論しても収束しない。頻度という数に変換すれば0か予算内かで機械判定でき、19本への一括適用も並列化できる。実際、オーナーの感覚的な指摘（「これ AI っぽい」）をその都度ルールの改定として取り込むことで、主観は規則に、規則は数に落ちていった。

**乖離6本を逆同期した理由**。drafts と公開版の不一致は「drafts を直しても公開に反映されない／再コピーすると改訂が消える」というフロー破壊の温床だった。web 側を正として drafts へ書き戻し19ペア一致に戻したことで、以後は通常の drafts→web フローへ復帰できる。

## 学び（一般化できるノウハウ）

1. **AI の文体癖は「定量化→0禁止と予算制の2階建て」で規制する** — 「AI っぽさ」の議論は頻度に変換すると収束する。存在自体が指紋になる要素は全面禁止に、修辞として有効な要素は最良の1箇所を残す頻度予算にする。「数えてから直す」を手順に固定すると、大量の記事へも並列で適用できる。

2. **文体ルールは生成・推敲・検査の3層に同じ正本を配線する** — 推敲パスだけに書いたルールは新規記事で再発する。生成時ガイド（出さない）・推敲手順（消す）・レビュー観点（検出する）の3層すべてから単一の正本を参照させると、ルール改定が1箇所で全層に効く。

3. **多バイト文字の grep は誤検出を前提に「機械で数えて目視で確定」** — 日本語の文字クラス指定はバイト単位で誤マッチする環境がある。機械 grep は候補列挙までとし、確定は目視で行う。この制約自体を検出ルールに明記しておくと、後続の作業者が同じ罠を踏まない。
